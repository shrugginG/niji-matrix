# 匿迹正式 Web · 本地第一版

纸白与墨绿的矩阵知识浏览系统。React + TypeScript + Vite；默认地址为 http://127.0.0.1:18091/。

## 启动

需要 Node.js 22.12+（或较新版本）与 Python 3。首次安装：

```bash
cd /home/shrugging/project/theory_research/niji-matrix-web
npm ci
python3 -m pip install -r ../niji-matrix/requirements-dev.txt
npm run dev
```

如果系统 Python 不允许直接安装包，请先创建并激活虚拟环境。已配置依赖的环境直接执行 `npm run dev`。按 Ctrl+C 停止。端口冲突时可用 `npm run dev -- --port 18092`。默认只监听本机回环地址。

首次启动会完整校验内容，再启动页面；当前内容规模通常需要数十秒。

## 单一内容源与自动更新

唯一内容源是同级 `../niji-matrix/`，与 `../tool/niji-matrix-review/` 一致。正式 Web 不依赖审阅服务运行，不创建需要人工维护的内容副本。

1. `scripts/export.py` 调用内容库现有 `scripts/validate.py`，执行 Schema 和跨对象引用校验。
2. 校验通过后导出版本化摘要索引和按对象拆分的详情 JSON。
3. Vite 监听规范内容、Schema 和脚本目录；修改、增加、删除 YAML 后自动重新校验导出。
4. 浏览器接收完成事件，同时每四秒检查状态，更新到新快照；无需手动刷新。
5. 校验失败时展示错误。页面若已有成功数据，会明确标记正在展示上次成功版本；初次加载失败不会偷偷使用旧数据。修复内容后自动恢复。

`public/data/` 和 `dist/` 均为生成产物，禁止手工维护。`planning/`、模板、原始 YAML 与 Markdown 不作为站点内容公开。当前本地版本展示全部规范对象及其真实生命周期，包括草稿；未来正式发布应另行确定准入范围。

可以用 `NIJI_MATRIX_ROOT=/absolute/path/to/niji-matrix npm run dev` 切换至结构完整的内容库（需要其 scripts 和 schemas）。测试导出可单独指定 `NIJI_DATA_OUT`，正常开发无需设置。

## 检查与构建

```bash
npm run build                 # 校验内容、导出数据、TypeScript 检查、生产构建
npm test                      # 真实对象层级、引用和详情完整性检查，需先生成数据
npx playwright install chromium
node tests/browser.mjs        # 需先在 18091 启动本地服务
node tests/source-links.mjs   # 原文/存档外链、新标签页、键盘和移动端
node tests/sync-browser.mjs   # 浏览器中的同步错误提示与自动恢复
node tests/watch.mjs          # 临时副本验证 YAML 监听，使用临时端口 18092
python3 tests/live-data.py     # 临时副本中验证内容变更、错误和恢复
npm run preview               # 本地预览构建产物，不监听 YAML
```

开发服务与 preview 使用同一默认端口，需先停止前者。生产构建为静态文件；本阶段不包含 Docker，后续将内容构建与 Web 一起打包。Docker 发布更新需要重新构建，除非另行启用挂载监听模式。

数据按内容哈希存放，状态文件原子切换，防止混用不同版本的索引和详情。开发时保留历史快照以支持正在打开的页面；需要清理时，停止服务后删除 `public/data/`，再启动重新生成。

## 公害仿真（本地第一版）

入口：`http://127.0.0.1:18091/simulation`。首次进入空白画布，后续自动恢复本机最近草稿。

- 人、云、端可拖入画布，也可点击添加；组织、云服务商及分组是可调整尺寸的容器。在实体属性的“所属容器”中设置归属。
- “网”定义社交、控制、互联网、以太网、内容分发等关系。从实体连接点拖到另一个连接点建立连线，属性栏可调整方向、线型、颜色、路径和控制点。
- 选择实体或连线后，可独立关联多个 NJT/NJS；父子技术独立勾选，并保存应用说明、事实/推断/假设依据及证据引用。
- 支持撤销/重做、删除、平移、缩放、适应画布、图层定位。删除容器会同时删除其内部实体、相关连线和技术关联，可撤销。
- 草稿保存至 IndexedDB。保存反馈失败时请导出 JSON。当前浏览器存储不会自动同步到其他设备，也不是直接写入仓库。
- 导入/导出使用 `.niji-scene.json`，保留实体、连接端口、关系语义、几何布局、容器层级、画布视角、来源与矩阵关联。导入创建独立副本，不覆盖已有草稿。
- “典型公害／典型案例”支持悬停、点击和键盘展开。打开预置文件会创建可编辑副本并跳转到本地草稿地址；刷新草稿地址仍恢复修改。该地址依赖当前浏览器 IndexedDB，跨设备请分享 JSON。
- 第一版预置远控木马**教学示意**与 Sality 扫描**资料抽象模型**，图中组织与节点不是完整真实拓扑。这里只做知识建模展示，不执行网络攻击，也不计算传播动力学。

文件位置：`scenes/catalog.json` 为菜单目录；`scenes/threats/`、`scenes/cases/` 为预置 JSON；`schemas/niji-scene.schema.json` 是独立于 React Flow 的场景合同。新增预置后运行构建即可收录。框架渲染通过适配器完成，不把事件处理器或运行时状态写入文件。

场景加载会校验格式版本、实体/连线/绑定 ID、端点及容器层级。无法解析或已弃用的矩阵引用会保留并提示，不自动删除；矩阵快照不同也会提示复核。场景不会修改 `niji-matrix/` 内容。

```bash
node --test tests/simulation-model.test.mjs  # 格式、往返、循环/错误引用、删除联动
node tests/simulation-browser.mjs           # 需启动 18091：拖拽连线、关联、撤销、保存/导入及预置恢复
```

连线可在选中后拖动两端圆点，改接同一实体的其他锚点或另一个实体。重连保留连线 ID、属性和技术关联，可撤销；旧路径控制点会清空以避免残留绕行。右侧也可选择起点/终点锚点，或点击“自动优化锚点”。自动模式根据实体的绝对位置（含容器）选择朝向合适的锚点；手动重连后使用固定锚点。旧版无模式标记、无控制点且默认右连左的线路会在加载时升级为自动模式。场景文件新增可选 `anchorMode`，兼容原有文件。

## GitHub Pages 自动发布

仓库主分支推送后由 `.github/workflows/deploy-pages.yml` 自动校验、构建并发布。`npm run build:pages` 使用临时公共资源目录，只生成当前快照，产物为 `dist-pages/`；它不会清除本地开发所用的历史数据或草稿。

Pages 版启用 Hash 路由，数据和案例附件均相对 Vite 基础路径加载。正常开发仍使用原来的路由和 YAML 自动更新。静态发布版取消四秒轮询，重新聚焦窗口时检查内容更新。

浏览器草稿按网站来源隔离，局域网草稿需导出 JSON 后在 Pages 网站导入。公开仓库不包含本地草稿、日志、依赖目录、测试截图或原始浏览器 HTML 捕获。
