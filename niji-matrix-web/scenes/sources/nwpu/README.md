# 西北工业大学事件：报道拓扑复刻

本案例按用户上传的《第58篇：美国安全局NSA入侵西北工业大学流程图梳理和分析（正式篇）》及十张总图/局部图整理。原作者为 ABC_123／希潭实验室，文章日期为 2023-04-22。它综合调查报道、其他公开资料及作者分析，不能把整张图自动视为独立核实的事件事实。

## 内容与复核

- `report.original.html` 保留用户上传的原始文件，不通过案例界面执行其中的脚本。
- `manifest.json` 保存原始 HTML 及十张图片的 SHA-256 校验值。
- 网站 `public/case-assets/nwpu/` 提供正文纯文本及原始图片，界面中的来源链接可直接打开。
- `topology-inventory.json` 是逐节点和连线清单；它记录原图位置、关系方向、显示名称及报道/推断/展示处理的性质。
- 正式场景为 `scenes/cases/nwpu-nsa-report.niji-scene.json`，由 `scripts/build_nwpu_scene.py` 生成。

当前包含 87 个节点、99 条连线、48 条矩阵关联（9 种父技术、4 种子技术）和 8 个局部视图。七个境外跳板和六个办公用户按图展开；49 台跳板的其余成员没有臆造。原图组织职责、匿名资源、平台能力、部署关系与流量路径使用不同关系类型，不统一解释成物理网络连接。

每个节点和连线都具有来源定位。正文工具能力与图中具体部署没有混作同一确定事实；“狡诈异端犯”的可能安装被标记为分析推断。工具和逻辑载荷使用虚线边框；工具族与具体“二次约会”部署实例分开。灰色分区、回传汇合点及从文字展开的逻辑节点明确标为展示处理。

矩阵关联是基于现有定义作出的分析映射，全部标为 inference。没有根据“反调试能力强”直接断言某个子技术，也没有从进程隐藏直接推断具体系统 API 拦截方式。每个关联保存应用说明与上传报道来源 ID。

## 阅读和编辑

在“公害仿真 → 典型案例”中选择本案。全景用于看总体结构；右上“场景视图”可跳至组织、资源、跳板、Foxacid、边界、运维、办公和工具局部。左下图例解释颜色；点击实体或连线后，右侧“来源与原图信息”可反查原图。

场景中的 reviewNotes 保存来源混合、原图占位符、难辨文字、译名及能力/实际部署区分等待核对事项。更精确的地址、年份或软件实现不从外部资料自行补入。

打开预置仍会生成独立可编辑副本，已有其他案例和用户草稿不会被替换。增删节点后，视图引用会同步清理。JSON 导入导出保留来源、分区、原始标签、图例、手动路径和矩阵关联。

## 重建与测试

在项目根目录执行：

```bash
python3 scripts/build_nwpu_scene.py
node --test tests/nwpu-scene.test.mjs
node tests/nwpu-browser.mjs
```

重建会覆盖本案预置和对应清单；先在生成脚本中修订内容，避免直接编辑预置后被覆盖。它不会修改矩阵 YAML。浏览器测试要求本地服务运行于 18091。
