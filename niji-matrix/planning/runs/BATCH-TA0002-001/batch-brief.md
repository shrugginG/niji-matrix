# BATCH-TA0002-001 研究与收敛约束

## 基线与范围

- 战术：TA0002 Execution / 攻击执行
- 固定基线：MITRE ATT&CK Enterprise 19.1
- 候选顺序：T1197、T1651、T1059、T1609、T1610、T1675、T1203、T1574、T1674、T1559
- 批次含义：对 Execution 页面固定顺序的前十个 ATT&CK 父技术逐一完成准入，不保证形成十个正式 NJT，也不设统一子技术数量。

## 父技术的直接行为对象与边界

|---|---|---|

| T1609 | 通过容器管理服务在既有容器内远程执行的命令 | 新建容器归 T1610；云虚拟机代理命令归 T1651；容器内普通 shell 仅在管理服务不是直接执行对象时归 T1059 |

## Niji 原生子技术规则

- 所有子技术必须由攻击者可稳定控制的匿迹变量、痕迹变化和防守观察差异共同支持，绝不继承 ATT&CK 子技术。
- 语言、平台、云厂商、容器编排器、IPC 协议、文件类型、工具名或产品名不能单独成为分类轴。
- 合法管理、开发、自动化和无障碍行为与攻击行为高度相似时，必须说明有意控制变量与正常操作造成的相似现象，并保留残余可观测痕迹。
- 每项机理必须形成“行为设计 → 痕迹变化 → 防守观察影响 → 匿迹效果”的完整因果链，证据强度不足时降为 hypothesis 或延迟，不写入不成立机理。
- 父技术截止于攻击者控制代码、命令或任务开始运行；持久化、提权、防御规避、横移与后续载荷效果按相邻战术另行分类。

## 跨候选与既有矩阵边界

- T1651、T1609、T1610 与 T1675 共享“受信管理面执行”表象，但分别以云来宾代理、既有容器、新容器部署和 hypervisor-to-guest 通道作为直接执行对象。
- T1059、T1559、T1574 与后续 T1106 均可能呈现本机进程活动；分类分别以解释器语义、进程间请求、执行路径重定向和原生 API 调用为锚。
- T1203 与 TA0001 的 NJT-0053、NJT-0054 以执行位置和入口阶段分界；本批次只覆盖客户端漏洞触发后的执行语义。
- T1610 与 NJT-0059 可信供应链入口以“目标环境内主动部署”和“交付前污染”分界，不复制初始入侵子技术。
- T1674 与后续 T1204 以“攻击者注入设备输入”和“用户基于呈现内容主动执行”分界。

## 证据与共享库治理

- 每个候选至少保留固定版本 ATT&CK 父技术来源；机理、子技术和防御结论必须由同级证据或明确推断强度支持。
- 先查询全局 Reference、Claim、Case、DET、NJA、MIT 与 REL；对象按 `reuse`、`extend`、`create`、`split` 或 `defer` 记录决议。
- 不为满足数量制造 Case 或 Relationship。检测策略按目标与分析集合定身份，Analytic 按逻辑和数据要求定身份，Mitigation 通过逐目标 Application 扩展。
- 批次正式对象保持 `review`，等待人工领域审查；机器通过不等于 `published`。
