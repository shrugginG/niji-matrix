# BATCH-TA0002-002 研究与收敛约束

## 基线与范围

- 战术：TA0002 Execution / 攻击执行
- 固定基线：MITRE ATT&CK Enterprise 19.1
- 候选顺序：T1106、T1677、T1053、T1648、T1129、T1072、T1569、T1127、T1204、T1047
- 批次含义：对 Execution 页面固定顺序中尚未处理的十个 ATT&CK 父技术逐一完成准入；候选数不保证正式 NJT 数量，也不预设 Niji 子技术数量。

## Niji 原生子技术规则

- 所有子技术必须由攻击者可稳定控制的匿迹变量、可说明的痕迹变化和独立的防守观察效果共同支持，不继承 ATT&CK 子技术。
- 平台、产品、编程语言、模块格式、调度器类型、云厂商、开发工具、文件类型、用户动作媒介或 WMI 类本身不能成为分类轴。
- 父技术的普通功能并不自动构成匿迹；正式范围只纳入攻击者有意借用受信执行外壳、分离因果链、降低内容可见性或贴合正常时序的实现。
- 每项机理必须形成“行为设计 → 痕迹变化 → 防守观察影响 → 匿迹效果”的完整因果链，并保留残余可观测线索和效果限制。
- 执行对象以攻击者控制代码、命令或任务开始运行为完成点；供应链入口、持久化、提权、横向移动与后续载荷效果由相邻对象处理。

## 跨候选与既有矩阵边界

- T1106、T1129、T1127 与现有 T1059、T1559、T1574 都可能呈现本机受信进程活动；分类锚分别是原生 API 调用、显式模块加载、受信开发实用程序代理、解释器语义、IPC 请求和执行路径重定向。
- T1677、T1648、T1072 与现有 T1651、T1609、T1610 均可能跨控制面执行；分类锚分别是流水线图、无服务器事件处理、集中软件部署、来宾代理命令、既有容器命令和新容器部署。
- T1053 与 T1569 以调度器是否保存未来触发条件、还是服务管理器直接承载或启动程序为界；跨重启只是可能属性，不单独决定归类。
- T1204 与 T1674、T1203 以真实用户的有意动作、攻击者伪造输入和漏洞自动触发三种直接触发源为界；可复用客户端触发检测时必须保留这种来源差异。
- T1047 以 WMI/CIM 管理基础设施和 provider-hosted 执行链为直接对象，不把所有远程管理或原生 API 调用并入 WMI。

## 证据与共享库治理

- 每个候选至少保留固定版本 ATT&CK 父技术来源；机理、子技术和防御结论必须由同级证据或明确的推断强度支持。
- 共享库查询显示本批次十项 ATT&CK 父来源均不存在；DET-000058、DET-000059、DET-000060、MIT-000057、MIT-000058 与 MIT-000059 是需要逐项判断的相邻复用候选，不因名称相似自动扩展。
- 临时对象使用 `EX2-<ATTACK-ID>-<TYPE>-<nn>`；正式 ID 仅在准入、子技术分类和共享对象复用结论收敛后由主 Agent 分配。
- 不为满足数量制造 Case 或 Relationship；缺少活动级案例时保持空数组并在研究限制中说明。
- 正式对象保持 `review`，等待人工领域审查；机器通过不等于 `published`。
