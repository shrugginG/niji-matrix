## 子技术规则

- 不读取或导入 ATT&CK 原子技术作为 Niji 子技术分类。
- 子技术按照匿迹实现变量区分，不按照身份平台、账户种类、字段、工具或媒介拆分。
- 每个候选都必须建立行为设计、痕迹变化、防守影响和匿迹效果的因果链。
- 账户状态变更不自动构成匿迹；必须证明攻击者有意改变可观察性、跨控制面关联成本、恶意与合法变更的可区分性或真实控制者的可归因性。
- 当前工作由主 Agent 顺序完成，不分派 Sub-agent，不提前分配正式 ID。

## 内容与证据门禁

- 每个候选的父行为证据：固定版本 ATT&CK T1098 页面锚定父行为与 TA0003 映射；平台实现、审计字段与控制效果另取官方身份平台或事件资料。
- 每项机理和子技术的结论级证据：行为设计、被改变的痕迹、观察影响和匿迹效果分别列明；若只能证明能力而不能证明攻击者有意匿迹，则降为 hypothesis 或 defer。
- NJT-0001 字段责任与论证深度对照方式：逐项回答定义、直接目的、概念锚、残余痕迹、正常反例、攻防前提、因果链和证据限制，不复制段落或对象数量。
- 重复正文、通用威胁模型和同文限制检查方式：与现有账户、身份、访问和资源开发对象逐段比较；任何只替换账户或平台名称的表述均重写或拒绝。
- 脚本仅承担的机械工作：ID 分配与同步、YAML 解析和排序检查、目录构建、Schema/规划/重复校验、Bundle 与 Web 测试。
