## 子技术规则

- 不读取或导入 ATT&CK 原子技术作为 Niji 子技术分类，也不按注册表、启动文件夹、plist、登录项、平台、用户或系统范围拆分。
- 优先审查“既有自启动对象挪用”：攻击者保留已存在启动对象的顶层身份或数量，只改变值、目标、参数或内容；必须证明稳定变量、内容差异痕迹、观察影响和独立防御需求。
- 新建伪装名称、罕见启动位置、条件激活和跨层间接链暂为研究假设；没有同级证据则 defer。
- 本批次由主 Agent 顺序完成，准入和 taxonomy 未收敛前不分配正式 ID。

## 内容与证据门禁

- 每个候选的父行为证据：固定版本 ATT&CK T1547 页面、操作系统官方启动/登录配置说明和至少一个现场案例。
- 每项机理和子技术的结论级证据：分别支持启动状态写入、值或目标变化、系统托管激活、进程来源变化和防守关联要求；只证明配置存在不能自动证明匿迹。
- NJT-0001 字段责任与论证深度对照方式：父级完整回答行为、直接目的、概念锚、残余痕迹、反例、攻防模型、因果链与证据限制；子项若成立，第一段匿迹特性以准确名称开头并说明 sibling 边界。
- 重复正文、通用威胁模型和同文限制检查方式：与 NJT-0063、T1053/T1569 Execution 对象和 T1098 对照，不复用身份或 BITS 语句；跨平台内容以共同启动链语义统一而非名称替换。
- 脚本仅承担的机械工作：固定基线提取、库查询、ID 分配、精确序列化、校验、Bundle 和 Web 测试。
