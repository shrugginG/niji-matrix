# BATCH-TA0003-013 人工审查整改记录

## 发现

2026-09-12 的 Persistence 横向审计发现，NJT-0093 及两个子技术虽然通过 Schema、引用连通和页面测试，但父级、子级、DET、NJA、MIT 与三项 Claim 共同依赖单一 ATT&CK T1556 页面。子技术攻击者模型、防守方模型和研究限制过短，无法完整说明权限、知识、反馈、保留期、正常反例和结论降级条件；原有 `high` 机理置信度也没有把直接行为证据与跨平台匿迹意图推断分开。

## 整改决议

- 保留 `adapt` 准入以及 NJS-0093-001/002 两个稳定变量；不导入 ATT&CK 子技术。
- 使用 Skeleton Key、Solorigate 与 UNC3944 结论级材料分别支撑选择性证明、联合信任和范围化策略例外。
- DET/NJA 以组件或信任版本、策略 old/new、逐请求 decision 和资源结果构成分支化谱系；MIT 分离验证器、联合信任、策略例外、独立差分和全路径恢复。
- 重写父子全部核心阅读字段，补足攻击者与防守方模型、残余痕迹、正常反例、证据限制及置信度变化条件。
- 将父级和子级匿迹机理校准为 `medium`；子技术存在性仍由直接案例保持 `high`。
- 增加候选级 Review Web 回归测试；只有 Schema、重复项、Bundle、双语页面和全套测试重新通过后才恢复 `review`。
