# BATCH-TA0005-006 五技术整改研究与收敛约束

- 基线固定为 enterprise-attack 19.1；总体 TA0005 计划保持 31 个工作项，当前交付子集为 T1211、T1564、T1574、T1070、T1202。BATCH-TA0005-005 已通过证据、taxonomy、内容、防御、机器、Bundle 与 Web 门禁。
- 本批超过默认一至三个父候选，是响应用户明确提出的“五个匿迹技术一个批次”。为避免规模压缩质量，五项候选分别保留独立来源查重、准入复核、taxonomy breadth、字段深度、防御对象、Bundle 和双语 Web 检查；T1564、T1574、T1070 不共享结论，逐项完成覆盖表和第二轮 taxonomy。原 BATCH007–010 材料保留为历史研究输入，但正式整改结果统一写入 BATCH006 集成摘要。
- T1211 的直接对象是利用软件缺陷让活动进入未记录、错误归因或受信执行边界；不与以权限提升为直接结果的 NJT-0102 合并，也不把直接终止或篡改防御控制纳入。
- T1564 的直接对象是保留工件真实状态但改变默认枚举、地址空间、检查表示或观察域。固定基线十四个 ATT&CK 子项只作广度先验，不直接继承；四个现有 Niji 变量必须分别补足结论级案例和目标特定防御。
- T1574 是对跨战术 NJT-0070 的复用审查。固定基线十二个 ATT&CK 子项须映射到解析候选阴影、稳定身份内容替换、运行时激活槽三类现有变量；若正文、案例和防御已达到 NJT-0001 责任深度，则不为“整改”制造无意义新对象。
- T1070 的直接对象是攻击者选择性删除、改写或迁移与自身活动相关的工件，使可重建链条收缩。原零子技术结论重新开放，至少比较内容/记录移除、关系清理、时间元数据改写和位置迁移的痕迹拓扑与防御差异。
- T1202 的直接对象是受信系统执行资产代理攻击者命令。原零子技术结论重新开放，比较一次性参数/标准输入代理与持久配置触发代理；与 NJT-0080 开发工具输入代理、NJT-012x 系统二进制代理和普通直接命令执行保持边界。
- 所有新 REF、CLM、CASE、DET、NJA、MIT 必须先查共享库；正式 ID 在准入、taxonomy 与复用决议收敛后由主 Agent 集中预留。候选数不保证新增父技术或子技术数量。
- 本批未通过五项候选的全部结论级证据、字段深度、机器、Bundle 和双语 Web 门禁前，不进入下一批正式写入；TA0005 始终保持 active/in-progress。
