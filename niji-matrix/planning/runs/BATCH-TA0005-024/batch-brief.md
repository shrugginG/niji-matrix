# BATCH-TA0005-024 五项正式 NJT 技术整改约束

- 基线固定为 enterprise-attack 19.1；本批按当前 Stealth 矩阵中的正式技术卡片处理 NJT-0061、NJT-0080、NJT-0116、NJT-0117、NJT-0118，不再以 ATT&CK 父候选数量代替整改技术数量。上一批 BATCH-TA0005-011 已通过证据、taxonomy、内容、防御、机器、Bundle 与双语 Web 门禁。
- 本批包含五个正式 NJT，超过默认一至三个候选，是延续用户明确要求的“五个匿迹技术一个批次”。每个 NJT 保留独立的证据查重、taxonomy、字段深度、防御、Bundle 与双语 Web 门禁；两个成熟跨战术能力包可保持原对象不变，但必须重新构建和审查。
- NJT-0061 直接对象是系统仍接受的真实身份或会话在情境、连续性和反馈状态控制下呈现为正常访问。复核三个既有子技术是否完整承担 Stealth 观察差异，并与凭据取得、授权修改和令牌操纵保持边界。
- NJT-0080 直接对象是受信开发 utility 解释不可信 project、manifest 或内联任务并代理执行。复核输入代理和无独立制品进程内执行两项既有变量，以及与普通系统实用程序代理、共享模块加载和运行时生成的边界。
- NJT-0116 直接对象是真实下层状态与上层系统信息查询视图之间的攻击者控制差分。原零子技术结论重新开放，至少比较枚举结果抑制、对象属性或状态伪造以及驻留层级是否真正产生不可互换防御。
- NJT-0117 直接对象是已激活恶意流程内部的攻击者排除谓词与保留结果。原零子技术结论重新开放，至少比较本地主机关键组件保留、跨主机角色保留、目标类型与谓词语法，拒绝按扩展名或产品机械建项。
- NJT-0118 直接对象是攻击者控制的可信来源呈现、用户判断、用户动作和未授权结果。T1684 固定基线包含人员冒充与邮件来源伪造两项实现，需比较关系身份仿冒与通信来源伪造的事实源、痕迹和缓解差异，并与 NJT-0114 可见特征身份替代保持边界。
- 所有 REF、CLM、CASE、DET、NJA、MIT 先查共享库；只有 taxonomy 和对象语义收敛后才分配正式 ID。ATT&CK 子项只作为规划广度先验，不导入为 Niji 子技术；五个正式 NJT 不保证新增相同数量的子技术或共享对象。
- 当前五项全部通过结论级证据、NJT-0001 字段责任、机器、Bundle 和双语 Web 门禁前，不进入最后四项正式 NJT 整改；TA0005 保持 active/in-progress。
