# BATCH-TA0005-025 最后四项正式 NJT 技术整改约束

- 基线固定为 enterprise-attack 19.1；本批按当前 Stealth 矩阵中的正式技术卡片处理 NJT-0119、NJT-0120、NJT-0121、NJT-0122，不再以 ATT&CK 父候选数量代替整改技术数量。上一批 BATCH-TA0005-024 已通过证据、taxonomy、内容、防御、机器、Bundle 与双语 Web 门禁。
- 本批包含四个正式 NJT，超过默认一至三个候选，是完成用户明确要求的正式矩阵整改。四项分别保留独立证据查重、taxonomy、字段深度、防御、Bundle 与双语 Web 门禁；任何一项未通过时不得宣称 27 项正式技术全部整改完成。
- NJT-0119 的直接对象是文档或内容中的外部模板引用把最终可执行、认证或展示内容移出原始对象，使静态检查与运行解析结果分离。开放式审查远程内容替换、认证副作用与缓存来源是否形成不可互换变量，并与 NJT-0115 载体嵌入保持边界。
- NJT-0120 的直接对象是普通扫描下不暴露功能的网络信号门控。固定基线两项 ATT&CK 实现只作广度输入，复核序列型信号与内核/socket-filter 单包匹配是否已经由现有子技术和防御分别覆盖。
- NJT-0121 的直接对象是攻击者把云工作负载放入历史未使用或监控覆盖较弱的区域，借区域级日志、安全服务与响应差异降低发现。原零子技术结论重新开放，至少比较区域选择与控制覆盖失配是否能稳定区分，以及账户/组织级全局视图是否将其收敛。
- NJT-0122 的直接对象是样本检测本地分析环境后改变执行结果。固定基线三项实现需要比较虚拟化/沙箱指纹、用户活动与时间三类条件所改变的痕迹和防御实验是否不可互换，不继承 ATT&CK 子项名称。
- 所有 REF、CLM、CASE、DET、NJA、MIT 先查共享库；只有 taxonomy 与对象语义收敛后才分配正式 ID。ATT&CK 子项是研究广度先验，不构成 Niji 输出配额；四个正式 NJT 不保证新增相同数量的子技术或共享对象。
- 本批完成只能把正式 Stealth 技术整改进度推进到 27/27。Niji-native gap、跨技术 taxonomy/防御收敛和人工领域审查仍是独立战术级门禁，TA0005 在这些门禁前保持 active/in-progress。
