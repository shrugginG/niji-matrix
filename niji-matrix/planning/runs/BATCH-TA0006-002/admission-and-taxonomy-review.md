# BATCH-TA0006-002 准入与二轮原生分类裁决

在分配任何本批 NJT/NJS 或共享 ID 之前，主 Agent 阅读 research-T1555.yaml、固定 ATT&CK Enterprise 19.1 工作簿、原始 Mandiant/KeePass/Keydnap 资料及平台审计文档，并同已完成的 NJT-0137/NJS-0137-003 和 NJT-0108 划界。上一批 BATCH-TA0006-001 的证据、内容、防御、make quality、Bundle、Web 和 API 门禁均已通过，保留 review。

## 准入：adapt，medium

T1555 的父行为是从受管理的密码存储取得凭据；Niji 范围只在攻击者跨越保管库授权或解锁边界并有证据支持秘密实际返回时成立。保管库文件、目录条目、API 列表或一次异常进程访问分别只证明发现、暴露或尝试，不自动证明取得可用口令。保留 T1555 的凭据获取对象，但按受信消费身份和解锁运行态两种可证实的匿迹因果链改写父语义。云秘密 API 的成功读取与攻击者保存或后继登录也分为不同证据层。T1552 拥有未受保护的散落秘密，T1003 拥有 LSASS/SAM/NTDS 等系统认证材料转储，NJS-0137-003 拥有取得可比对材料后的离线候选测试；NJT-0108 只拥有替代存储视图的介质路径。

## ATT&CK 六项覆盖与第二轮 taxonomy

| 固定子项 | 实现广度与研究决议 |
|---|---|
| T1555.001 Keychain | 授权消费者读取可支持受信身份轴；复制受保护库只进入待证副本轴。 |
| T1555.002 Securityd Memory | Keydnap 的旧版 securityd 内存路径支持运行态轴，不以 macOS 服务名建子项。 |
| T1555.003 Web Browsers | 数据库复制与运行态读取跨多个保管库可能发生；副本本身未证明密码返回。 |
| T1555.004 Windows Credential Manager | CredRead 说明登录令牌下的单项返回，是父级实现；缺少独立匿迹变量证据。 |
| T1555.005 Password Managers | 受信触发器、受保护文件及短暂明文为跨产品变量提供对照，不按管理器品牌拆分。 |
| T1555.006 Cloud Secrets Management Stores | 身份和资源级秘密内容 API、审计启用条件支持受信消费轴；云平台名不是子项。 |

第一轮对齐以上实现；第二轮离开 ATT&CK 标签，测试消费身份、解锁时点、材料状态、观察域、读取节奏、目标范围和跨设备来源。低频窄范围读取缺少刻意稀释与阈值失效的一手证据，跨设备控制面分离缺少稳定兄弟边界及独立防御，因此两轴暂缓。平台或产品轴拒绝。

正式接受两项 Niji 原生子技术：“受信消费身份转用”控制保管库看到的授权调用主体与真实控制者的分离，残余痕迹是配置、来源、秘密集合及输出；“解锁运行态旁路取密”控制秘密返回的位置与时间，保管库逐项 API/提示可能缺席，但进程访问、转储与后继输出可观察。前者以 Mandiant KeePass 受信解锁后明文导出实验为直接效果证据，云 API 只支持实施与审计模型；后者以 Keydnap 旧版 securityd 分析及 KeePass 官方明文窗口为结论级证据，现代平台效果需单独核实。两项的 DET/NJA 数据平面和 MIT 措施不同。

“密文保管副本离线转移”保留在规划层，不建正式 NJS。UNC1069 的钥匙串/浏览器库复制及 UNC2465 的 Bitwarden 数据库导出改变逐项审计视角，但公开事件未把同一副本连接到成功解锁或秘密返回。可对父级记录此暴露边界和条件性防御风险，不能用两起事件与另一个产品的解锁能力拼接为已观察到的完成链。将来若出现同一事件的密文副本、解锁状态和可用秘密结果，可重新审查这一轴。六项覆盖和第二轮记录解释正式结果少于 ATT&CK 实现广度的原因。

## 共享库与防御裁决

REF-000366 的 Sysmon ProcessAccess 语义直接复用；REF-000382 是同一 Storm-0501 原文，可扩充 locator 以涵盖 KeePass 配置查找，但不据“启动 KeePass”推定明文返回。UNC1069 与 Mandiant 2026 勒索事件资料在库中已为 REF-000229 与 REF-000473，直接复用并扩充 locator；不为相同 URL 再建 Reference。原研究提议的 Keydnap 与 Mandiant 红队案例可各建一个按来源限制的 CASE；副本两案例暂缓为正式 Case。父级建立阶段、受信消费、运行态和副本边界四项原子 Claim，不以副本 Claim 宣称已获明文。

正式防御建立两项策略：受信消费者差分下分本机/云端两个 Analytic；运行态进程访问到秘密结果单独一项 Analytic。副本检测与缓解留在研究材料，待证据链闭合后再进入正式目标引用。Bitwarden 导出事件只支持其组织库部署，Google Data Access 需要启用，Windows Sysmon Event 10 只证明进程访问，不证明秘密恢复。Mitigation 分别针对消费者权限/配置和运行态隔离/短暂明文窗口，Application 必须写清目标限制。正式对象完整双语字段需按 NJT-0001 的责任和论证深度逐项复核；无人工作域评审前只能保持 review。
