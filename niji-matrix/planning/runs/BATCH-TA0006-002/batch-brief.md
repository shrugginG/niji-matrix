## 直接对象和相邻边界

T1555 的直接对象是由操作系统、应用或专门服务管理的凭据存储与已解锁秘密。正式准入必须证明攻击者从保管边界获取可用凭据材料，并说明访问痕迹如何因受信读取路径、消费身份、材料状态或观察面而改变。列举一个文件路径、产品或 API 并不自动证明匿迹。T1552 拥有散落在普通文件、注册表、聊天或历史中的未受保护凭据；T1003 拥有操作系统认证材料转储；已完成获取后的离线候选测试归 NJT-0137/NJS-0137-003；输入截获归 T1056；已得到的应用令牌归 T1528。NJT-0108 的替代存储视图只解释获取介质，不能单凭快照读取冒充 T1555 的保管库解锁或秘密使用结果。

## 固定子项广度先验和 Niji 分类门槛

ATT&CK 19.1 的六项为 T1555.001 Keychain、.002 Securityd Memory、.003 Web Browsers、.004 Windows Credential Manager、.005 Password Managers、.006 Cloud Secrets Management Stores。这些是平台与保管库实现线索，必须逐项或逐簇在研究覆盖表中决议，不复制成 NJS。研究者须执行第二轮开放 taxonomy 搜索，至少检查受信消费者身份借用、存储对象离线复制、解锁后内存可见性、秘密 API 读取范围与时间、跨设备或云控制面来源分离等可能的受控变量。每个拟议 NJS 要有稳定的行为变量、对照前态、痕迹变化、防守观察差、独立场景和不同的 Detection/Mitigation 价值。若收敛为零或一项，主 Agent 必须逐轴解释广度差；不能为了贴近六项数量创造无证子项。

## 证据和防御

固定 ATT&CK 父页锚定父行为与战术映射，不自动证明某个密码管理器、云库或内存路径的匿迹效果。优先使用保管库厂商 API/安全文档、原始事件调查及可复核的实验；把“访问存储”“返回秘密”“秘密被攻击者保留”“后续身份使用”分别定级。合法备份、同步、迁移、受信工作负载读取和用户主动导出必须进入正常对照。Detection Analytic 应写明各平台实际可获得的审计源、字段、关联窗口和盲区，不能把文件读取、进程附加与云 GetSecretValue 混成一个只替换名称的通用规则。Mitigation 要针对保管库控制面、解锁或导出权限、审计保留与凭据轮换分别说明作用和限制。
