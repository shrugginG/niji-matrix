# BATCH-TA0007-001 T1087 与 T1010 研究与收敛约束

## 基线与范围

- 战术：TA0007 Discovery / 环境测绘；固定版本为 `enterprise-attack` 19.1。
- 总体范围：`program-inventory.md` 从本地 MITRE 19.1 技术表逐行冻结的 34 个 TA0007 父候选，包括同时映射 Stealth 的 T1622 和 T1497；正式进度只按 TA0007 矩阵计算。
- 当前交付批次：T1087 Account Discovery / 账户发现，T1010 Application Window Discovery / 应用窗口发现。两项信息对象不同，可分别研究并并行交接；主 Agent 在收到全部结果后统一处理相邻边界与共享库。每项都须独立通过证据、分类、双语内容和防御门禁。
- 前一批次：无。预检时 TA0007 正式技术、决策和子技术均为零，ID 无预留；基线质量检查仍在运行。相邻战术由其他工作流程同步写入，本批不能把其新增对象算作 TA0007 进度。
- 当前批次未通过前，不开始下一批的正式写入。两个候选不预设都能准入，更不预设 NJS 数量。

## 子技术与证据规则

- T1087 在 19.1 有四项 ATT&CK 子项：T1087.001、.002、.003、.004，按本地、域、邮件、云账户类型划分。这只是实现广度先验。研究至少两个不同匿迹变量轴，逐项或逐簇记录覆盖决议，不以账户种类直接命名 NJS。
- T1010 在 19.1 无 ATT&CK 子项，仍须开放搜索稳定的攻击者可控匿迹变量。不能把窗口、标题或操作系统种类当成天然子项。
- 每个拟议 NJS 都须说明变量、前提、行为设计、痕迹变化、防守观察差异、兄弟边界、独立证据和有区别的防御价值。证据不足时保留为研究假设。
- ATT&CK 父页面只锚定行为和战术映射；子项、匿迹机理、检测字段与缓解效果需要结论层级相符的独立资料。合法管理查询、辅助功能、用户支持、窗口管理与常规脚本是必须检验的反例。

## 共享库和内容门禁

- 研究者先查全局 REF、CLM、CASE、DET、NJA、MIT、REL。T1087 与既有账户创建、有效账户和身份状态对象可能近似，但检测目标与数据模型未确认前不得直接复用；T1010 同样不得挪用普通进程发现或软件发现对象。
- 临时键使用 `D07-01-T1087-*` 与 `D07-01-T1010-*`。Sub-agent 只提交各自的研究结果和暂存交接，不分配正式 ID，不修改正式矩阵或共享库。
- 父子双语字段逐项对照 NJT-0001 的定义、特性、范围、场景、攻防模型、机理、证据和限制责任。防御对象必须具有可实施的数据字段、关联逻辑、误报、盲区、调优与逐目标缓解应用；通用文字或名称替换不能过门禁。
- 仅把脚本用于提取固定清单、YAML 序列化、ID 同步、校验、构建和测试，不用脚本按候选名生成读者正文或防御分析。

## 并行安排与收敛

- 第一轮并行：一名 sub-agent 研究 T1087，另一名研究 T1010；各自交接到 `planning/runs/BATCH-TA0007-001/` 的独立文件或最终消息。
- 主 Agent 等待两份结果，处理跨候选边界、来源和语义对象查重、准入、Niji taxonomy 收敛、正式 ID 与写入，再进行质量、Bundle 和双语 Web 验收。
- 对任何无法由资料支持的细分、机理或案例不做正式化；公开或被动查询也须明确证明对可观察性、关联、区分或归因产生何种变化。
