## 1. 先行准入结论

**建议 `retain`，父级准入置信度 high；Niji 匿迹机理置信度 medium；当前正式 Niji 子项 0，taxonomy 建议 `deferred`。** 固定 ATT&CK Enterprise 19.1 工作簿 `data/mitre-attck/enterprise/v19.1/excel/enterprise-attack-v19.1-techniques.xlsx` 的 `techniques` 表第 96 行：ID `T1580`、名称 `Cloud Infrastructure Discovery`、战术 `Discovery`、平台 `IaaS`、`is sub-technique=0`；全表无 `T1580.*` 行，故 ATT&CK 子项数与 ID 分别为 `0` 与 `[]`。这是规划广度先验，`original_attack_subtechniques_imported: false`，不得从 API、资源种类或平台名派生 NJS。[固定版父页](https://attack.mitre.org/techniques/T1580/)与工作簿父行锚定行为；网页会更新，版本裁定以本地工作簿为准。

**准入理由（zh）：** 攻击者在 IaaS 控制面取得实例、快照、网络、存储容器、数据库等已存在资源及其配置关系，以决定后续横移、持久化或数据访问目标，恰与固定版 T1580 一致。Expel 的实际应急记录在被盗 IAM 访问键下观察到 ListBuckets、DescribeInstances、DescribeDBInstances，随后出现针对安全组和实例的操作，证明该父级不是单靠产品能力推想。匿迹意义限于攻击者借用有效身份执行外观上正常的只读清单行为，使事件存在但恶意性难判；单凭低频、分页、正常 API 或合法凭据不能证明规避意图。保留父级语义比为争取 Niji 子项而改写信息对象更稳妥。[Expel 原始事件分析](https://expel.com/blog/finding-evil-in-aws/)

**Admission rationale (en):** An adversary reads existing IaaS instances, snapshots, network components, storage containers, databases, and their configuration relationships to choose later movement, persistence, or data access. That is the fixed T1580 parent behavior. Expel's firsthand response observed ListBuckets, DescribeInstances, and DescribeDBInstances under compromised IAM keys, followed by security-group and instance actions, so the parent is supported by observed activity rather than tool capability alone. Its defensible stealth relevance is the use of a valid identity for ordinary-looking read operations: the events remain visible, while classifying their intent becomes harder. Low volume, pagination, a normal API, or a valid credential alone does not prove an evasion motive. Retaining the parent keeps its information object stable.

## 3. 父级行为、边界与原生匿迹轴

判定单位是**直接获得的 IaaS 资源实体及关系清单**，例如实例与网卡/安全组、快照与卷、桶与访问配置、数据库与网络边界。T1526 回答服务能力是否启用/可访问；T1538 回答 GUI 控制台中的访问与阅读路径；T1619 回答已知容器**内部**对象名、前缀和对象元数据。一个 API 同时回传服务名和资源名时，以攻击者直接求取的信息和后继用途裁定；打开 GUI 并不自动建立另一父级，也不把 CLI/API/GUI 当 NJS。与 NJT-0131 的既有**身份**清单、NJT-0132 的当前**窗口**视图、NJT-0121 的低覆盖区域**资源创建**分开。云资源清单读取也不等同于创建、修改、下载内容或外传。

## 4. 父级双语核心字段与机理提案

**名称 / Name：** 云基础设施发现 / Cloud Infrastructure Discovery。**摘要 / Summary：** 攻击者读取已存在的 IaaS 资源及关系，在有效身份的正常只读活动中隐藏目标选择。 / The adversary reads existing IaaS resources and relationships while target selection can blend into ordinary read activity under a valid identity.

**definition_and_concept** — zh：云基础设施发现是在已进入的 IaaS 环境中取得具体资源实体、属性及相互连接的行为。其直接成果是可用于判断下一步进入、修改或取数路径的资源图，而不是云服务是否存在这一能力目录。攻击者可通过资源 API、已有资源视图或其他可读清单完成这一目标；查询接口本身不定义父项。 / en: Cloud Infrastructure Discovery is the acquisition of concrete IaaS resources, attributes, and relationships inside an accessed environment. Its direct output is a resource graph useful for choosing later access, change, or data paths, rather than a catalogue of which cloud services are available. Resource APIs and preexisting readable inventories can serve that end; the interface itself does not define the parent.

**stealth_characteristics** — zh：已获访问键下的实例、桶和数据库读取保留了控制面审计，却常与资产盘点、故障排查或安全治理使用同一类操作。攻击者可借用这类正常读路径降低单条事件的恶意可区分性，但身份、来源、时间、请求方法及后继写操作仍可关联；异常是否显现依赖读事件收集、账户/区域聚合和合法作业基线。 / en: Reads of instances, buckets, and databases under an obtained key remain in control-plane audit records, yet use the same operations as inventory, troubleshooting, and security governance. Using that normal read path can make any single event harder to classify as malicious, while identity, origin, time, method, and later writes remain correlatable. Visibility depends on collecting reads, combining accounts and Regions, and knowing approved inventory jobs.

**scope_boundary_definition** — zh：纳入为求取具体 IaaS 资源实体、配置与连接而进行的读取；服务目录或启用状态归 T1526，GUI 的导航与展示路径归 T1538，桶内对象键/前缀归 T1619。合法 CSPM、IaC 刷新、资源治理和应急盘点与此共享 API 形态，必须靠授权主体、作业窗口、查询覆盖和后继结果判别。读到资源后修改安全组或启动实例是后继行为，不再算本父项的直接动作。 / en: Include reads aimed at concrete IaaS resources, configuration, and connections. T1526 owns service availability, T1538 owns the GUI navigation and viewing path, and T1619 owns keys and prefixes inside a storage container. Authorized CSPM, IaC refresh, resource governance, and incident inventory share API shapes, so actor authorization, job schedule, query coverage, and subsequent actions matter. A later security-group change or instance start is a successor, not this parent's direct act.

**application_scenarios** — zh：取得有限云凭据后，攻击者可能先寻找可达实例、相关网络控制、备份快照与数据库，再决定哪条路径值得进一步使用。Expel 案例显示从 S3/EC2/RDS 资源读取转向安全组与实例动作的具体顺序；这仅证明该案后继，不代表每次资源发现都会导致变更。 / en: With limited cloud credentials, an adversary may locate reachable instances, related network controls, snapshots, and databases before choosing a next path. Expel documents a concrete transition from S3/EC2/RDS reads to security-group and instance actions; that successor is observed in that case, not guaranteed for every discovery attempt.

**attacker_model** — zh：需要能访问目标账户、项目或其可读资源视图的身份/会话，并受 IAM、区域、视图与存储状态的范围约束；不预设管理员权限或全组织视野。若复用历史 state/索引，还需要取得那个副本和接受过期、不完整的资源图。 / en: The attacker needs an identity or session that can access the target account, project, or readable resource view, and remains constrained by IAM, Region, view, and stored-state scope. Administrative rights and organization-wide visibility are not assumed. Reusing old state or an index also requires access to that copy and acceptance of stale or partial results.

**defender_model** — zh：防守方可有云管理事件、身份/STS、Config 或 Resource Explorer 事件、作业台账、端点与远端 state 访问日志，但各云、事件类别、项目和区域的收集条件不同。AWS 只读日志通常不含返回资源集；GCP Data Access 常须启用，Azure Activity Log 通常不含读取。缺日志时应标为盲区，而不是推断攻击者确已避审。 / en: Defenders may have management events, identity and STS logs, Config or Resource Explorer events, approved-job records, endpoint and remote-state access logs, but collection varies by cloud, event class, project, and Region. AWS read events generally lack returned resource sets; GCP Data Access usually needs enabling, and Azure Activity Log normally omits reads. Missing logs establish an observation gap, not proof of deliberate evasion.

**stealth_mechanism proposal：** `NM-FD` primary，medium，证据 `REF-02/03/04`。短摘要 zh「借用有效身份的资源读取外观融入正常盘点」；en “Blend resource reads under a valid identity into ordinary inventory activity”。分析 zh：攻击者借用有效访问键调用与合法盘点相同的只读资源接口，生成的是有身份和方法的真实审计事件，而非修改告警；依赖“写入异常”或单事件 API 名的防守方难将该读行为与正常盘点区分，直到把新主体/来源、跨资源读取及后继变更相连。Expel 证明入侵者这样列举，正常表象导致的实际漏报并未测量，所以机理只到 medium。 / en: The adversary uses a valid key to call read-only resource interfaces also used by legitimate inventory, producing real identity-and-method audit events rather than a change alert. A defender keyed only to writes or isolated API names can have difficulty separating those reads from approved inventory until a new actor or origin, cross-resource reads, and later changes are joined. Expel establishes the adversarial reads, but no measured miss rate, so the mechanism remains medium confidence. `NM-BT` 仅对**已经证明**的读事件未收集、索引视图转移或 state 本地读可考虑，当前不建议作为父级笼统机理；`NM-ST` 对 `AX-03/05` 暂缓。

**subtechnique_taxonomy narrative** — zh：当前没有经一手恶意活动与痕迹比较共同支持的稳定子项。下一轮优先审查“从已有资源视图取图而非实时服务专属枚举”的读取位置变量，分别核验聚合查询、索引搜索与 state 文件的日志面和独立防御差异；跨身份、跨区域、分页、节奏仅为待证轴。 / en: No stable child currently has both firsthand adversarial activity and a supported trace comparison. The next review should test the reading-location variable—acquiring a resource graph from an existing view instead of fresh service-specific enumeration—while separately checking aggregate queries, indexed search, and state files for their logging and defense differences. Identity spread, Region spread, pagination, and cadence remain unproven axes.

**research.limitations** — zh：Expel 支持实际资源读取与后继，但没有请求参数级分页/过滤、攻击者规避指令或同案检测效果；其“用 RunInstances 启动既有停止实例”的表述与 AWS API 定义冲突，因此不把该句提升为确证的状态转换。AWS、GCP、Azure 文档证明日志类别和产品能力，不能代替目标租户的采集配置、保留和访问授权；正常 CSPM/IaC 与恶意读取可同形。若拿到同案查询参数、跨账户完整日志、state 读取取证和批准作业台账，应重评匿迹机理与子项。 / en: Expel supports the observed resource reads and successors, not pagination or filtering parameters, an evasion instruction, or a measured detection outcome. Its description of RunInstances starting an existing stopped instance conflicts with the AWS API definitions, so that sentence is not treated as a verified state transition. AWS, GCP, and Azure documentation establishes event classes and product capabilities, not a target tenant's collection, retention, or authorization. Approved CSPM or IaC reads can look the same. Same-case request parameters, complete cross-account logs, state-access forensics, and approved-job records would justify reassessing the mechanism and child taxonomy.

## 5. 暂缓子项的双语核心内容（仅研究稿）

`D07-02-T1580-SUB-01` **既存资源视图转读 / Retrieval from a Preexisting Resource View**，状态 `hypothesis; defer`，绝非已分配 NJS；若将来正式化，`lineage.attck_subtechnique_inherited: false`。

**summary** — zh：攻击者从已有配置、索引或 state 视图取资源图，使本次发现不表现为一串服务专属资源枚举。 / en: The adversary acquires a resource graph from an existing configuration, index, or state view, so the present discovery is not a series of service-specific enumeration calls.

**definition_and_concept** — zh：变量是本次资源信息从既有可读视图取得，而非逐个向权威资源服务发起新枚举。只有视图确已包含目标资源并被攻击者读取时才成立；Config/Explorer/Terraform 是待比较的实现，不是兄弟子项。 / en: The variable is obtaining the present resource information from an already readable view rather than issuing fresh enumeration to each authoritative resource service. It applies only when the view contains the target resources and is actually read; Config, Explorer, and Terraform are implementations to compare, not sibling children.

**stealth_characteristics** — zh：既存资源视图转读会把本次资源图获取从 EC2/RDS/S3 服务专属列表事件移到 Config/Explorer Search 或 state 读取面，致使只盯服务专属 API 的检测失明。它仍留有聚合查询或文件访问痕迹，且视图可能过期、被权限和索引裁剪；Explorer 的查询条件在 CloudTrail 遮蔽增加语义判断困难。 / en: Retrieval from a Preexisting Resource View shifts the present acquisition from EC2/RDS/S3-specific listing events to Config or Explorer Search, or to state access, so a detector limited to service-specific APIs misses it. Aggregate queries or file access still leave traces, and the view may be stale or filtered by permissions and indexing. Explorer's CloudTrail redaction of query conditions further limits semantic judgment.

**scope_boundary_definition** — zh：纳入已经存在的资源配置/关系视图被用来回答 T1580 的资源实体问题；如果只是看云服务是否开通，归 T1526；如果重点是 GUI 导航，归 T1538；如果 state 中只是对象键，归 T1619。合法 CSPM 与 IaC state 使用是主要反例，远端 state 读取还可能属于存储对象访问而需另查审计。 / en: Include use of a preexisting configuration or relationship view to answer T1580's concrete-resource question. Service enablement belongs to T1526, GUI navigation to T1538, and object keys inside storage to T1619. Authorized CSPM and IaC use are major counterexamples; remote-state reads may also be storage-object access requiring separate audit review.

**application_scenarios / attacker_model / defender_model** — zh：攻击者若先取得有权读聚合器、搜索视图或 IaC state 的身份，可在准备后继资源操作前从这些入口拿部分资源图，但必须接受视图时效和覆盖边界。防守方若仅有服务专属 Describe 告警，会缺本次读取；若补齐 Config/Explorer 管理事件与 state 存储/端点审计，可看到替代入口，但 AWS 只读响应不还原完整结果。 / en: After obtaining an identity authorized for an aggregator, search view, or IaC state, an adversary could obtain a partial resource graph before later operations, subject to the view's freshness and coverage. A defender watching only service-specific Describe calls would miss this acquisition; Config or Explorer management events and state storage or endpoint audit could reveal the alternate entry, although AWS read responses do not reconstruct the full result.

**mechanism / limitations** — 备选 `NM-BT`，仅架构推断，`hypothesis`，证据 `REF-07/08/09`。**不升正式**，因为尚无可信同案证明攻击者选用该入口，并且文件读取与聚合 API 的审计条件及缓解措施可能不同，主审需测试是否应 split。 / Candidate `NM-BT` is architectural inference only and remains a hypothesis, supported for feasibility by `REF-07/08/09`. Do not formalize without a credible adversarial case; file reads and aggregate APIs may differ enough in audit and mitigation to require a split.

## 6. 可实施防御设计与逐目标效果

**`D07-02-T1580-DET-01`（建议 create）** 检测目标：在获授权但异常的 IaaS 资源图获取中识别陌生主体/来源、跨资源关系探索与后继高风险操作；覆盖候选父 T1580，`enterprise`，分析集为下述两个 NJA 候选。不得把 DET-000118 扩为此策略：其目标是低覆盖区域**资源创建**谱系，数据与响应不同。ATT&CK DET0169 只作检测线索，不把其阈值当验证结果。

**`D07-02-T1580-NJA-01`（直接资源读取，建议 create）**：输入 AWS CloudTrail **read management** 事件 `DescribeInstances`、`DescribeDBInstances`、`ListBuckets`，以及核实后的网络/快照资源读方法；`HeadBucket` 只在相应 **data event** 已启用时纳入，不能错列管理事件。必要字段 `eventTime,eventSource,eventName,userIdentity.arn/userIdentity.accessKeyId,userIdentity.accountId,recipientAccountId,awsRegion,sourceIPAddress,userAgent,readOnly,errorCode,requestParameters`；关联身份/STS 事件与批准作业台账，并可接后继 `AuthorizeSecurityGroupIngress`、实例启动等写事件。窗口先以 24 小时同一 key/session、7 天主体/角色基线与 30 天例行作业历史做**部署待校**，绝非来源给出的经验阈值；按 account+Region+principal/session 聚合后再看跨账户/区域图；ListBuckets 是账户桶清单，不应仅凭其日志的 awsRegion 当作桶所在区域或拆成区域资源结果。去重页请求且保留分页元数据，不能用页数推断实体数。多类资源读取、首次来源/主体、偏离批准范围或随后变更共同提高评分，不以单条 List/Describe 判恶。误报包括 CSPM、IaC refresh、成本治理、灾备、运维/应急盘点；以登记的工作负载身份、作业时段和预期账户/区域做分层基线，但保留其凭据新来源与异常后继告警。盲区为 read 选择器关闭、Event history 单账户/单 Region/90 天、跨分区或 opt-in 区域未接入、只读响应为空、请求参数缺失、合法身份被盗及低速长期拼接。AWS `REF-02/03/04/05/06/12` 支持输入和案例；**窗口及评分是工程建议，需实测**。

**`D07-02-T1580-NJA-02`（既存资源视图，建议作为父级补充分析；子项暂缓）**：输入 CloudTrail 管理事件 `config.amazonaws.com` 的 `SelectResourceConfig/SelectAggregateResourceConfig` 与 `resource-explorer-2.amazonaws.com` 的 `Search`，加聚合器/视图权限、批准 CSPM 作业台账和可得的远端 state 对象访问或端点 state 文件读取。必要字段同上，额外 `viewArn` 或聚合器名、调用者身份、事件类别、请求结果/错误；QueryString 在 Explorer 日志中被遮蔽，不得声称有完整查询语义。按身份+会话+账户+查询入口 24 小时关联至后继 EC2/RDS/S3 目标访问，跨账户聚合时明确源账户与查询聚合器账户；远端 state 使用哪个存储审计通道须部署前逐后端核实，不先写死 S3 GetObject。误报为常规 CSPM/资产治理/成本报告、IaC 计划或恢复、SOC 调查；盲区为 state 本地副本、查询条件遮蔽、Config 未记录资源与索引延迟、跨账户日志缺失。AWS `REF-07/08/09` 支持入口和部分日志能力，恶意用途及阈值尚无同案证据，故 NJA 仅低/假设置信度，主审可 defer。

**跨云可移植性限制：** GCP 不可用 Admin Activity 代替 Compute Data Access `list/get`；须逐 project、service、method 检查启用与 `protoPayload.authenticationInfo.principalEmail`、`methodName`、`resourceName` 可得性。Azure Activity Log 通常不记录读取，不得编造 Azure Resource Graph 查询事件字段；只有部署实证另一可用审计源后，才能把 Azure 加入正式 NJA 的 `platforms`。S3 桶存在性 `HeadBucket` 属数据事件，桶清单 `ListBuckets` 与桶内对象 `ListObjects/V2` 不共用未核实的通道：后者由 T1619 独立审查，`REF-000513` 不能直接证明其日志覆盖。

**`D07-02-T1580-MIT-01`（建议 create；可与现有身份最小权限措施比较）** 可实施 Measure：①逐工作负载审查并收紧不必要的资源 List/Describe、Config 聚合器、Explorer view 和 state 读取权限，允许的清单范围与责任人/到期绑定；注意 EC2 Describe 的资源级限制依具体 IAM action 而异，不能承诺能按单实例精准屏蔽。②针对所有业务账户/区域保留 read management，核实 HeadBucket 等目标 data event 的启用，集中健康监测；GCP 按项目开启所需 Data Access，Azure 另建可核实的读审计方案。③独立保护 IaC state 与聚合视图，审阅远端存储 ACL 和异常下载，并标注合法 CSPM/IaC 主体及作业窗口。父目标 `T1580` 的 use 是缩小可见资源面并保留跨账户读事件；expected effect 是减少未授权身份能取得的资源图、提高异常读与后继动作的可关联性；limitation 是业务运维仍需广泛只读权限、被盗的合法盘点主体仍可读取、历史副本和跨云缺口不能靠 IAM 一项消除。对暂缓 `SUB-01` 的**条件性** use 是限制 Config/Explorer 视图及 state 副本访问并审计替代入口；expected effect 是降低预存图可得性并把读取移入可观察通道；limitation 是本地已复制 state 不可追溯、聚合索引可能过期/裁剪。此条件性应用不得写进正式 MIT `applications`，除非子项获准并有正式 target_ref。
