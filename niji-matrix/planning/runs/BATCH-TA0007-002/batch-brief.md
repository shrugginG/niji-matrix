## 子技术、证据与防御门禁

- 五项在固定 19.1 工作表中均无 ATT&CK 子技术；零项只表示无需版本子项覆盖表，仍必须开放搜索 Niji 原生匿迹轴。ATT&CK 的平台、服务、工具、浏览器字段、资源种类、API 或 GUI 名称不能直接成为 NJS。
- 每个拟议子项须具有稳定且由攻击者控制的变量、行为设计→痕迹变化→防守观察影响→匿迹效果、前提、场景、兄弟和跨父边界、结论级资料与有区别的防御价值。公开/被动读取和合法控制台行为不能仅因低噪声被认定为匿迹。
- ATT&CK 父页只锚定父行为与 Discovery 映射。案例必须明确区分实际使用、工具能力、架构推断、攻击者意图及实测检测效果；不足者降置信度、标假设或 defer，不为完成五项而强制 retain。
- DET 说明检测目标和覆盖对象，NJA 必须列实际可取得的日志通道与字段、逻辑、窗口、关联键、误报、盲区和调优。MIT 应有可实施 Measure，并对每个获准 NJT/NJS 单独写 use、expected effect 和 limitation。各项必须与既有云审计/身份/资源治理对象查重，不能只替换对象名称。
- 父子双语内容逐字段对照 NJT-0001 的定义、匿迹特性、范围、场景、攻防模型、机理证据和研究限制。若五项呈统一一段式、相同威胁模型、同文限制或通用 Analytic，视为门禁失败。

## 并行研究与共享库治理

- 第一轮：T1217、T1580、T1538 各由一名 sub-agent 研究；第二轮：T1526、T1619 各由一名 sub-agent 研究。每名研究者只写自己在本目录下的 `Txxxx-handoff.md`，或在最终消息给出同等结构；临时键前缀 `D07-02-Txxxx-*`。不分配正式 ID，不修改正式矩阵或 REF/CLM/CASE/DET/NJA/MIT/REL 共享库。
- 第一轮后主 Agent 汇总公共来源候选、检查 URL/语义重复并刷新 catalog；第二轮据此复核边界。五份交接齐备前不统一准入、不分配正式 NJT/NJS 或共享库语义 ID、不写正式技术。
- 每份交接至少含 retain/adapt/exclude 建议及双语理由、固定版父与零子项确认、已审查的多个原生轴、证据表及结论边界、父子核心双语内容、防御数据模型、相邻对象与共享库 reuse/extend/create/split/defer 建议。
- 脚本仅执行机械提取、序列化、编号、同步、审计和构建；正式读者正文、准入理由、Claim、机制链、Analytic 逻辑及 MIT Application 必须逐候选人工收敛。
