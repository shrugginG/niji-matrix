## 分类与证据门禁

- ATT&CK 子技术数均为 0，只作为固定版广度记录。每项必须检索多个可能的稳定变量，例如读取位置、查询范围、条件门控、时间/来源分布、权威视图与缓存视图差异、返回语义可见性；产品、API、平台、资源类别、路径类型和工具名称本身不能成为 NJS。
- T1622 研究必须从既有正式包出发：若 TA0007 的 Discovery 目标和 TA0005 的调试状态检查/行为门控是同一事务，建议 retain + reuse NJT-0106，并审查 technique `classification.tactic_refs` 扩展；只有直接对象或机理不同才可 split，不能因战术名不同复制正文、防御或子技术。
- 对其他候选，先作 retain/adapt/exclude，再决定是否存在新 NJT。每个正式 NJS 需要攻击者可控变量、稳定边界、痕迹变化、防守观察差、前提、场景、结论级来源和不同防御价值。父页只锚定父行为，不自动证明匿迹机理或子项。
- 事件、工具文档、产品能力、架构推断、攻击者意图与实测检测效果分层。证据只支持父行为时，子项保持 hypothesis/defer；不得为完成五项而强制准入或创造子项。
- 父子正文逐字段对照 NJT-0001 的定义、匿迹特性、范围边界、应用场景、攻防模型、机理、证据和研究限制。四个新候选不得共享同一通用威胁模型、限制、Analytic 或 MIT Application。

- DET 定义具体检测目标；NJA 必须列部署中真实可得的数据通道和字段、关联窗口与键、误报、盲区和调优。MIT 必须给可实施 Measure 及逐目标 use/effect/limitations。发现行为与后继执行、利用或收集必须在逻辑中分开。
