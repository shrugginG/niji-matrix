# BATCH-TA0009-001 Collection 首批研究与集成约束

本计划以 `matrix.yaml` 固定的 MITRE ATT&CK Enterprise 19.1 为基线。TA0009 共 17 个父候选，完整清单记录在 `planning/tactics/TA0009.yaml` 和本批 `program-inventory.md`。当前 TA0009 正式矩阵为 0 个 NJT、0 个 NJS；不存在前批门禁。本批仅处理 T1560 Archive Collected Data、T1074 Data Staged、T1119 Automated Collection。三项均涉及已取得数据的处理或收集节奏，需要逐候选研究后统一裁定“获取、自动汇聚、暂存、归档”的边界；三名研究者各自负责一个候选，主 Agent 独占正式 ID 和共享库写入。候选数不保证正式 NJT 或 NJS 数。

T1560 的直接对象是已收集数据的归档容器及其形成过程；T1074 的直接对象是待后续使用或外传的数据暂存位置与汇聚过程；T1119 的直接对象是规则化、重复或自动触发的数据获取。压缩格式不是 T1074 的定义，暂存位置不是 T1560 的定义，定时任务或脚本存在也不能单独证明 T1119 的匿迹。研究者须检验是否存在攻击者稳定控制的匿迹变量、对应痕迹变化与防守观察差异，并明确正常备份、同步、打包与数据处理的相似行为。

ATT&CK 子项只作为研究范围与广度先验：T1560 的 3 项、T1074 的 2 项、T1119 的 0 项均不得直接导入 NJS。T1560 至少检验两种不同匿迹轴；零子项的 T1119 仍需开放式搜索。每项实质机理、子项存在性、检测字段和缓解效果需有结论级证据。研究交接保存在本目录，使用临时键；准入判断先于任何正式 NJT/NJS 或共享对象分配。

主 Agent 等待全部研究结果后，依次完成跨技术边界与共享库的 reuse、extend、create、split 或 defer 决议，再写入正式对象。每项候选需分别通过证据、分类、双语内容深度、可实施防御、`make quality`、Bundle 和中英文 Web 检查，才可进入 `review`。本批门禁未通过前，不开始下一批的正式写入；人工领域评审前不发布。
