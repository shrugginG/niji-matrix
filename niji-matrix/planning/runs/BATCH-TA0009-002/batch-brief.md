# BATCH-TA0009-002 Collection 五候选研究与集成约束

本批继承 `matrix.yaml` 固定的 MITRE ATT&CK Enterprise 19.1 基线，整体范围仍为 TA0009 的 17 个父候选。上一批 T1560、T1074、T1119 已通过准入、结论级证据、分类、双语内容、共享库、`make quality`、Bundle 与 Web 门禁，处于 `review` 等待人工领域评审。当前正式矩阵为 3 个 NJT、4 个 NJS；其余 14 个父候选仍未完成。本批按用户明确要求选择其中 5 项：T1557、T1213、T1114、T1185、T1123。候选数不保证新建 NJT/NJS 数；跨战术复用、改写或排除须先经准入判断。

五项是本次交付范围而非五项同时跳过门禁的许可。T1557 已在 TA0006 有仅限凭据路径的 NJT-0136 和两项子技术，需判断 Collection 的通信内容获取是否可共用该对象；不可把凭据目的直接当作一般内容收集证据。T1213 有 6 个 ATT&CK 子项，是本批主要复杂候选：必须逐项或按可解释簇形成覆盖表，做第二轮 taxonomy 搜索，保留代码仓库、协作平台等实现差异与 Niji 匿迹变量之间的距离。T1114 的 3 个子项也须至少检验两个不同匿迹轴。T1185 和 T1123 虽无 ATT&CK 子项，仍须开放式检索稳定匿迹变量。

每项直接行为对象与邻接边界：

- T1557：攻击者主动介入通信路径以接触正在交换的信息。被动嗅探由 T1040 处理，凭据证明和会话令牌由现有 TA0006 对象及相邻技术处理；本批不得仅凭网络重定向便宣称内容已被收集。
- T1213：从协作、代码、知识库或业务信息库取得内容。T1530 负责云对象存储，T1602 负责配置存储库，T1114 负责电子邮件，普通资源发现与实际内容读取要分开。库类型、产品和 API 名称不自动成为 NJS。
- T1114：从邮箱、邮件服务器或客户端邮件存储取得消息及附件。账户取得、邮箱规则、邮件外传、浏览器会话控制是相邻过程；要区分持续读取模式与一次合法导出。
- T1185：攻击者在活跃浏览器会话中截取、改写或接管会话相关交互。Cookie/令牌结果、首次钓鱼入口、输入捕获和一般页面脚本执行须与会话中介的直接对象划清边界。
- T1123：获取环境或用户音频。输入捕获、屏幕与视频采集、设备权限建立及录音文件后续归档/暂存分别判断；麦克风设备、操作系统或文件格式不能直接成为 NJS。

每名 sub-agent 只提交一个候选的研究交接：固定基线父级与 ATT&CK 子项广度记录，retain/adapt/exclude 建议，证据 URL 与具体支持范围，Niji 原生候选轴、痕迹差异、防守观察差异，双语父子内容草案，独立的 DET/NJA/MIT 建议与局限。第一轮由 T1557、T1213、T1114 研究者并行；主 Agent 等三份结果后再派第二轮 T1185、T1123，且在五份结果全部到齐前不作正式 ID 和共享库写入。主 Agent 独占准入裁决、跨技术边界、共享对象复用/拆分、正式 ID、规范写入与验收。

五候选规模的理由是用户明确指定下一批为五项，且其中 T1557 有已形成的跨战术对象可供比较；研究仍以每候选独立证据和内容深度为原子门槛。若某候选证据不足或边界不稳定，应保留 defer/exclude 或 `draft`，不得通过缩短正文、套用通用检测缓解或跳过第二轮分类来凑齐数量。批次只有在全部候选通过证据、分类、双语、共享库、质量、Bundle 与 Web 门禁后进入 `review`；人工领域评审前不发布，也不开始下一批正式写入。
