# BATCH-TA0009-003 屏幕与视频捕获研究约束

本批继承 `matrix.yaml` 的 MITRE ATT&CK Enterprise 19.1 基线。TA0009 固定清单共有 17 个父候选；前两批已使 8 个 NJT、12 个 NJS 进入正式矩阵并保持 `review`，剩余 9 个父候选。本批按既定计划只处理 T1113 Screen Capture 与 T1125 Video Capture。上一批五项已通过准入、结论级证据、Niji 原生分类、双语内容、共享库、`make quality`、Bundle 和 Web 门禁；人工领域评审仍待完成。两项相邻的视觉采集行为需要逐项独立研究及共同边界裁决，因此设为双候选批。候选数不保证 NJT/NJS 数。

T1113 的直接对象是从桌面、应用窗口或屏幕会话取得显示像素或截图。T1125 的直接对象是从摄像头、视频通话或其他视频输入取得图像序列或帧；ATT&CK 也允许间隔图像替代连续视频文件，因此不得仅凭“静态文件/视频文件”分界。若同一会议既截屏又取摄像头帧，应分别证明各输入面与结果。T1123 负责音频；T1010/NJT-0132 负责窗口和应用状态发现，其触发条件可与后继视觉采集同现但不代替采集证据；T1056 负责文字与界面输入，T1074/T1560 负责后续暂存与归档。正常远程支持、会议录制、无障碍、质检与用户主动截图均须作为反例。

固定工作簿中 T1113 与 T1125 均没有 ATT&CK 子项。这只是研究广度先验，不能免除开放式 Niji 分类搜索。每个拟议子项必须具备稳定且有意控制的匿迹变量、对应痕迹变化、独立防守观察差、前提与场景、结论级证据和目标特定防御价值。应检验但不预设成立：目标窗口或前台状态门控、捕获节奏稀释、借用受信图形/会议进程、应用接口依附、内存或缓冲处理及残余权限/设备指示。按屏幕/摄像头品牌、操作系统、API、文件格式或 ATT&CK 示例工具拆分不成立。工具具备能力不等于现场实际规避检测。

两名 sub-agent 各研究一个候选，只在本目录提交带唯一临时键的研究交接和必要覆盖记录：先作 retain/adapt/exclude 准入建议，再提供可核验来源 URL 与具体支持范围、父子双语内容草案、机理因果链、可实施 DET/NJA/MIT、正常反例及局限。不得分配正式 ID，或修改正式矩阵、共享库与战术计划。主 Agent 等两份结果后统一裁决两项边界、查重、分配 ID、写入和验收。脚本仅作机械序列化；未过证据、内容、质量、Bundle 和中英文 Web 门禁前不进入 `review`，人工评审前不发布。
