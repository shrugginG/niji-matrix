# BATCH-TA0009-004 五类数据来源研究与集成约束

本批继承 `matrix.yaml` 的 MITRE ATT&CK Enterprise 19.1 基线。TA0009 固定清单共有 17 个父候选；前三批已有 10 个 NJT、13 个 NJS 进入正式矩阵并保持 `review`，剩余 7 个父候选。本批按用户明确要求处理 5 项：T1115 Clipboard Data、T1005 Data from Local System、T1039 Data from Network Shared Drive、T1530 Data from Cloud Storage、T1602 Data from Configuration Repository。上一批 T1113/T1125 已通过准入、证据、跨技术去重、双语内容、共享库、`make quality`、Bundle 与 Web 门禁。候选数不保证 NJT/NJS 数；每项仍须独立准入和语义门禁。

五项共享“从既有数据位置读取内容”的相邻边界，适合在一批中统一裁决来源所有权，又必须避免按位置名称机械产生子项：

- T1115 的直接对象是实际取得剪贴板内容。剪贴板轮询、变化通知、粘贴操作和历史记录只是触发或传感器线索；T1056 负责输入捕获，浏览器表单或按键不能仅因稍后进入剪贴板而重复归类。
- T1005 的直接对象是从已控制主机的本地文件、数据库、应用数据或其他本地存储取得内容。T1083 等 Discovery 只证明路径或对象存在，T1119 负责通用自动收集范围/轮次；本地主机位置本身不是匿迹变量。
- T1039 的直接对象是从网络共享驱动器或共享文件系统取得内容。共享发现、挂载和凭据使用是前提；T1074 负责取得后的集中暂存，T1570 等传输对象不替代源读取证据。
- T1530 的直接对象是从云对象、文件或相关存储服务取得内容。列举桶、对象或服务属于 Discovery，OAuth/集成身份控制另有现有对象，下载后的外传与暂存分别由后继技术处理；云供应商或 API 名称不能定义 NJS。
- T1602 的直接对象是从配置存储库取得设备、协议、拓扑或运行配置内容。固定版两个 ATT&CK 子项（T1602.002 与 T1602.001）仅为网络设备配置导出和 SNMP MIB 实现广度，不得导入 NJS；配置存储位置、协议或厂商不是稳定匿迹变量。

每个候选先作 retain、adapt 或 exclude 判断，再开放检索 Niji 原生轴。研究应检验但不预设成立：选择性/谓词读取、借用正常同步或备份主体、读取视角与权威审计错位、跨身份/来源分散、事件触发、低频增量、版本/快照读取和不触发普通文件事件的替代接口。每项拟议轴必须说明攻击者控制变量、痕迹变化、防守观察差、前提、结论级证据、正常反例与独立防御价值；与 NJT-0135 状态化增量、NJT-0143 信息库选择、NJT-0086 集成身份、NJT-0134 暂存及其他正式对象重复时必须交还原所有者。

研究分两轮并行。第一轮由三名 sub-agent 分别负责 T1115、T1005、T1039；主 Agent 等三份完成后再派第二轮 T1530、T1602。每名研究者只在本目录写带唯一临时键的 handoff 和必要覆盖表，不分配正式 ID，不修改正式矩阵、共享库或战术计划。T1602 必须记录两个 ATT&CK 子项的 planning-only 覆盖决议；其他四项虽为零子项，仍须开放式搜索。五份结果全部到齐后，主 Agent 统一处理跨技术重复、准入、共享库 reuse/extend/create/split/defer、正式 ID 与写入。

父技术和任何子技术必须以 NJT-0001 的字段责任为质量基准，完整双语覆盖定义、匿迹特性、范围边界、场景、攻击者和防守方模型、机理、证据与限制。DET/NJA/MIT 必须按数据来源差异写出可实施字段、关联窗口、对象或会话键、正常备份/同步/索引/合规流程反例及目标特定应用，不能用统一“异常读取”模板替换名称。脚本只作机械序列化。全批证据、内容、质量、Bundle 和中英文 Web 门禁通过后方可进入 `review`；人工领域评审前不发布，也不开始下一批正式写入。
