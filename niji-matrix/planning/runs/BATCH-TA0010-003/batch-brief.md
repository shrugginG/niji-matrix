# BATCH-TA0010-003 研究与收敛约束

## 基线与范围

- 战术：TA0010 Exfiltration（数据渗出）。
- ATT&CK domain/version：enterprise-attack 19.1；总体固定清单 9 个父候选，仅统计 TA0010 正式矩阵。
- 当前最终批次：T1567 Exfiltration Over Web Service、T1537 Transfer Data to Cloud Account。
- 批次规模与理由：两个候选共同涉及服务端数据交付、合法云/Web 基础设施和账户归属，但一个以外部 Web 服务为接收媒介，一个以同服务跨账户共享、同步或备份为直接对象。并行逐项研究后由主 Agent统一解决云存储、Webhook、合法服务身份和账户边界重叠。
- 前两批门禁：7 个父技术、13 个 Niji 子技术已处于 review；完整 make quality、Bundle、121 项 Web 测试和双语页面检查通过，人工评审未完成。
- 本批通过后才能进行 TA0010 战术级缺口、交叉边界与完成状态审查。候选数量不保证正式 NJT/NJS 数量；exclude 只保存准入决策。

## 父技术边界

| 候选 | 直接行为对象 | 与相邻技术边界 |
|---|---|---|
| T1567 | 攻击者把失窃数据提交给已有的外部 Web 服务、API 或 Webhook，由该服务承担接收或转交 | T1537 以同一云服务内账户/租户所有权变化为核心；T1048 以不同于 C2 的协议或接收关系为核心；T1041 复用既有 C2；仅把文件放到受害 Web 根目录并外部取回属于前批暂缓缺口，不自动归 T1567 |
| T1537 | 攻击者利用共享、同步、复制、导出或备份机制，把数据控制权转移到其控制的另一云账户/租户 | 同账户内暂存不成立；下载后再上传由相应收集与外传通道承担；T1567 的第三方服务上传不要求同服务账户所有权转移 |

## 子技术和证据规则

- 不导入 ATT&CK 子技术。T1567.001/.002/.003/.004 的代码仓库、云存储、文本存储和 Webhook 只是实现/服务维度。
- T1567 有 4 个 ATT&CK 子项，必须至少检验两个不同 Niji 匿迹轴，逐项或逐簇完成覆盖决议；不得按服务产品或媒体类型拆分。
- T1537 无 ATT&CK 子项，仍须开放搜索账户归属、服务内复制、审计主体变化、对象标识连续性、授权工作流借用和删除/撤销生命周期等轴。
- 每个正式 NJS 必须有稳定攻击者变量、痕迹变化、防守观察差异、残余痕迹及差异化防御。合法 SaaS/云行为、共享链接和备份不能仅凭外观视为匿迹。
- ATT&CK 页面只锚定父行为与战术映射；子项、机理、防御字段、缓解效果和案例必须有结论级原始或权威证据。
- 父子双语内容逐字段对照 NJT-0001，禁止模板化威胁模型、统一限制和只替换名称的 DET/NJA/MIT。
