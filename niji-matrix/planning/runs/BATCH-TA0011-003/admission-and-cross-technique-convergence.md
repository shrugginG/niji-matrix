# BATCH-TA0011-003 主 Agent 准入与跨技术收敛

五名候选研究分两轮完成，五份 handoff 均通过 YAML 与临时证据引用闭包检查。主 Agent 在全部结果到齐后统一复核准入、11 条候选原生轴、现有正式对象和共享库；此前没有分配规范 ID或写入共享库。

## 准入结论

| ATT&CK 父候选 | 结论 | 正式父级直接对象 | 主 Agent 保留的原生子轴 |
|---|---|---|---|
| T1090 Proxy | adapt | 实际承载 C2 或操作者访问的中介网络转发路径 | 被攻陷网络出口归属借用；分舱中继观察链断裂；跨层路由权威分离 |
| T1092 Communication Through Removable Media | retain | 两端已受控后，以往返介质完成异步命令—执行—结果闭环 | 身份定向介质信箱；跨角色遍历状态门控 |
| T1095 Non-Application Layer Protocol | adapt | 无真实应用事务的网络/传输层或平台局部持续控制通道 | 无连接分组序列控制；主机栈旁路控制平面 |
| T1102 Web Service | adapt | 合法外部服务的账号、API 与持久资源作为 C2 控制资源 | 共享服务控制命名空间间接化；服务对象任务状态会合 |
| T1104 Multi-Stage Channels | adapt | 多个 C2 通道按引导、操作、任务或结果角色进行非失败式交接 | 引导—操作通道交接；任务—结果通道功能分离 |

T1092 的 retain 不继承任何 ATT&CK 子项；其固定基线没有子项。T1090 的四项和 T1102 的三项 ATT&CK 子项仅在各自 handoff 与 taxonomy review 中记录覆盖，不复制为 NJS。T1095、T1104 的零 ATT&CK 子项不限制开放搜索。

## 子轴之间的所有权

- **T1090 被攻陷网络出口归属借用 vs TA0042 NJS-0044-002**：TA0042 对象拥有出口池的攻陷、准备和轮换；T1090 子项只在这些或单个受控第三方节点实际转发 C2 后，拥有目标侧把真实第三方网络归属误作操作者来源的观察差。可双重归类，防御分别是资源完整性/生命周期与实时双侧会话/目标最后跳。
- **T1090 分舱中继 vs T1104 多通道角色**：前者按路径相邻性和管理域分割端到端观察责任，同一逻辑会话可贯穿所有中继；后者按控制功能或能力阶段把不同 C2 通道分工。跳数或多地址本身不构成任一子项。
- **T1090 跨层路由权威 vs T1102 共享服务命名空间**：前者在同一边缘会话中比较 TLS SNI/证书与 HTTP Host/:authority、CDN 账户和实际源站；后者比较合法 provider 与真实 tenant/account/app/token/resource。路由权威差不是服务账号命名空间差，可并列发生。
- **T1090/T1102 vs NJT-0160**：NJT-0160 处理应用协议自身的 resolver/broker 中介或接收地址；T1090 需要通用网络转发腿或共享边缘路由，T1102 需要合法外部 Web 服务资源参与控制。单纯使用 HTTP/MQTT/DNS 不足以映射新父级。
- **T1092 vs NJT-0058/NJT-0194/T1105**：NJT-0058 终止于介质播种到另一主机触发，NJT-0194 终止于数据经物理介质外传，T1105 只要求文件到达；T1092 要求两端已受控并存在命令向内、动作和结果向外的闭环或同一工具的可复核重复周期。单向投递和宿主不可见区域不建立本批正式 NJS。
- **T1095 vs T1571/T1572/T1205/T1132/T1573**：端口异常、完整内层协议封装、魔术激活、编码和加密各有直接对象；T1095 两子项分别由攻击者自定义的无连接会话状态以及绕开主机 IP 栈的 VMCI/AMT 等控制平面定义。raw TCP 可留父级核心。
- **T1102 服务对象会合 vs T1104 任务—结果分工**：前者围绕同一持久 service object 的 create/update/read/delete 与端点结果形成异步状态循环，即使只有单向任务投递也可部分成立；后者要求不同通道按任务取得和结果回传承担不同角色。多个 Web 对象或单双向标签不直接生成 NJS。
- **T1104 引导—操作交接 vs NJT-0153 备用通道**：T1104 由选择、能力升级、地址配置或阶段完成触发；NJT-0153 由原路径失败/不可达触发。普通 payload/process stage 没有多个逻辑 C2 通道时不属于 T1104。

## 证据级别裁决

- T1090 三轴均保留。第一轴通过“准备 vs 实际转发”与 NJS-0044-002 分离；第三轴只在相同边缘会话可比较路由权威时成立。
- T1092 两轴保留；ProjectSauron 只支持外传的宿主不可见区，因此该候选 deferred。GoldenDealer 未观察的一般文件复制组件不进入正式事实。
- T1095 两轴保留。PingPull 命令示例是研究环境测试，ShadowPad 是主动协议仿真，PLATINUM 来源不确定 AMT 的配置来源；均在 Case/limitations 中降格表达。
- T1102 两轴保留。T1102.001 中动态定位器属于 T1568；T1102.002/.003 的方向只是同一命名空间/对象生命周期的完成度。HAMMERTOSS 的 locator、隐写和外传分别由相邻对象承担。
- T1104 两轴保留。LunarWeb 的 output URL 是能力/边界证据，有限观察中与 command URL 相同，不能用它单独证明任务—结果通道分离；该子轴主要由 BlackWater 直接支持，正式置信度按来源校准。

## 共享库决议

- 固定来源 `REF-000625` 扩展 locator 至本批五候选；不重复建 STIX 来源。
- 精确复用 handoff 标明的既有 REF、CASE 和字段文档；`REF-000053`、`REF-000639` 等只扩展 locator/notes，不复制 URL。
- T1092 扩展 `MIT-000053` 的 T1092 父子 applications；T1102 扩展 `MIT-000203` 的父子 applications。两者控制概念和 Measure 不变。
- T1090、T1095、T1104 的 DET/NJA/MIT 全部按新目标和关联逻辑创建。T1092 的双向往返结果门与现有传播/外传策略不同，DET/NJA split/create。T1102 DET/NJA 需要 provider namespace、object 生命周期和 endpoint outcome，创建而不复用仅词面相近对象。
- 全部新 REF 已对刷新后的共享库做精确 URL 复核，未发现漏报重复。正式写入后仍需 `audit_duplicates.py --fail-on exact` 和可能相似项审查。
