# BATCH-TA0011-004 五候选研究与集成约束

## 基线、范围与批次规模

`matrix.yaml` 固定 MITRE ATT&CK Enterprise 19.1。TA0011 的 18 个父候选已完整登记，前三批 8 个正式父技术和 17 个 NJS 均通过证据、分类、双语内容、针对性防御、`make quality`、Bundle 和 Web 门禁并保持 `review`。本批按用户明确要求处理五个连续父候选：T1105 Ingress Tool Transfer、T1132 Data Encoding、T1205 Traffic Signaling、T1219 Remote Access Tools、T1568 Dynamic Resolution。这是允许的上限批次，分两轮由每名 sub-agent 独立研究一个父技术。批量目的在于统一收敛“入站对象、消息表示、隐藏激活、合法远控会话、动态目的地”边界，不合并逐候选证据、准入、分类、内容或防御门禁。候选数不保证新建五个 NJT；既有跨战术父技术可在独立准入后复用。本批未通过全部门禁前，不开始最后一批正式写入。

## 候选直接对象与批内边界

| 候选 | 直接行为对象 | 必须收敛的边界 |
|---|---|---|
| T1105 | 从外部系统或 C2/替代协议把工具或文件送达已受控环境，并形成可验证的目标侧到达 | 与 TA0008 的 NJT-0130 横向工具传输、一次 Web 下载、T1071 应用会话、T1102 服务对象、T1132 内容编码和 T1104 阶段组件取得区分；来源边界和到达结果必须明确 |
| T1132 | 对 C2 命令或结果应用可逆字符/二进制表示变换，使防守在规范化前不能直接使用原内容 | 与 NJT-0152 消息混淆、TA0005 NJT-0115 通用内容表示遮蔽、T1573 加密、T1001 噪声/载体及协议本身的合法编码区分；标准/非标准标签不能直接成为 NJS |
| T1205 | 特定魔术值或有序信号触发原本不暴露的监听、转发或恶意功能 | 现有 TA0005 NJT-0120 及其端口序列/内容匹配子项应作为跨战术复用候选；与 T1095 持续低层 C2、T1571 端口选择、T1090 路径转发、T1104 阶段交接区分 |
| T1219 | 滥用合法远程访问软件、IDE 远程开发或远程访问硬件建立交互控制会话 | 与 T1133 远程服务入口、T1563 会话劫持、T1090 代理/隧道、既有有效账户/远程会话对象及普通批准支持区分；软件/硬件产品类别不是 NJS 边界 |
| T1568 | 让植入与基础设施共享算法、DNS 状态或计算规则，在运行时求得当前 C2 域名、地址、端口或后续定位器 | 与 NJT-0153 失败备用通道、T1102 dead-drop/service object、T1104 引导材料、T1090 路由权威及普通 DNS 解析区分；DGA/Fast Flux/DNS Calculation 名称不能直接复制为 NJS |

同一事件可并列归类，但每个 Niji 子项必须由一个稳定、攻击者可控的匿迹变量拥有。主 Agent 等全部五份交接后，统一裁决重叠、跨战术复用和共享对象。

## ATT&CK 子项与原生分类门禁

固定基线中 T1105 无子项；T1132 有 T1132.001/.002；T1205 有 T1205.001/.002；T1219 有 T1219.001/.002/.003；T1568 有 T1568.001/.002/.003。子项仅作实现和广度先验。T1219/T1568 必须至少研究两条性质不同的匿迹轴并逐项记录覆盖决议；零子项的 T1105 仍须开放搜索。正式 NJS 必须有稳定变量、痕迹变化、防守观察差、兄弟/相邻边界、前提、结论级证据和差异化防御。编码算法、工具、服务品牌、硬件型号、域名格式、记录类型、协议、端口和目标类别都不能单独成为 NJS。

## 跨战术复用要求

- T1205 必须先审查 TA0005 `NJT-0120`、`NJS-0120-001/002` 及现有 DET/NJA/MIT。若父行为和原生变量相同，应新增独立 `DEC-TA0011-T1205` 并扩展 `classification.tactic_refs`，不得复制 NJT/NJS。
- T1105 必须比较 TA0008 `NJT-0130` 的“独立文件到达”结果门，判断外部入站与横向到达是否属于同一父行为的战术语境扩展，或因来源边界/防御不同而新建。
- T1132 必须比较 NJT-0152 与 NJT-0115，避免把同一可逆表示变换在三个父级下重复建子项；正式归类可以并列，但变量所有权要唯一。
- T1219/T1568 需检索现有远程会话、身份情境、外部服务、动态目的地和基础设施对象，不能只按 ATT&CK 名称创建新防御内容。

## 证据、内容和防御门禁

每个候选先完成 retain/adapt/exclude，再分配 NJT/NJS。固定 ATT&CK 页面只锚定父行为和战术映射。子项、机理、检测字段、控制效果和案例结论优先使用原始事件/样本分析、标准和权威产品日志文档；区分现场观察、样本能力、实验复现及传感器模型推断。父级和所有正式子项逐字段对照 NJT-0001，完整覆盖定义、匿迹特性、残余痕迹、范围和正常反例、场景、攻防模型、机理、证据与限制，不共享换名模板。

Detection Strategy/Analytic 必须包含原始到规范字段映射、数据源、关联键、窗口、可观测信号、误报、盲区和调优。Mitigation 必须给出可实施 Measure 及每个目标的 use、expected effect 和 limitations。缺少目标端到达、内容恢复、触发结果、远控会话所有权或动态解析反馈时必须降低结论，不能用理论字段冒充部署证据。

## 并行研究和共享库所有权

第一轮 sub-agent：T1105、T1132、T1205；第二轮：T1219、T1568。每名 sub-agent 只写 `planning/runs/BATCH-TA0011-004/<ATTACK-ID>-*` 暂存文件并使用唯一临时键；不分配正式 ID，不修改战术计划、正式矩阵或任何共享库。主 Agent 等全部五份结果后，统一处理 admission、跨技术边界、reuse/extend/create/split/defer、正式 ID、写入和验收。人工领域评审前正式对象保持 `review`。
