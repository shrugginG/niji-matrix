# BATCH-TA0040-001 研究与收敛约束

## 基线与范围

- 战术：TA0040 Impact（影响释放），以当前正式 TA0040 矩阵为计数依据。
- ATT&CK domain：enterprise-attack；version：19.1。固定清单为 [TA0040-attack-19.1-inventory.yaml](../TA0040-attack-19.1-inventory.yaml) 中的 15 个父候选。
- 当前交付批次：T1485 Data Destruction、T1486 Data Encrypted for Impact，共 2 个候选。两者同属破坏数据可用性，证据、结果和恢复语义可能重叠，适合同批交叉收敛；各自仍有独立准入和内容门禁。
- 前一批次门禁：无，本批为首批。本批未完成前，其他候选仅在计划中，不进入正式写入。候选数不预设 NJT/NJS 数量。

## 父技术边界

| 候选 | 直接行为和信息对象 | 交叉边界 |
|---|---|---|
| T1485 | 删除或毁坏文件、对象及数据内容，使其不再按原用途可用 | T1486 的直接状态转换是加密及密钥控制；T1561 的直接目标是磁盘内容或结构擦除。后续 T1490 改变恢复能力，不能代替毁坏证据。 |
| T1486 | 加密数据以妨碍合法读取或业务处理 | 与正常静态加密、数据外传前打包、T1485 的删除或覆盖区分；后续抑制恢复归 T1490。 |

## 子技术和证据规则

- 固定基线 T1485 有 T1485.001 一个 ATT&CK 子项（生命周期触发删除），T1486 无 ATT&CK 子项；仅作为研究广度先验，不导入 NJS。
- 研究攻击者可控制且稳定的匿迹变量，并逐项列出行为设计、痕迹变化、防守观察差异、前提与残余痕迹。删除对象类型、加密算法、平台或工具名称自身不能构成子技术。
- 对每个 ATT&CK 子项或维度给出 parent-core、niji-variable-candidate、adjacent-technique、evidence-deferred 或 not-stealth-distinct 决议；无 ATT&CK 子项也须开放搜索。
- 先以官方 ATT&CK 19.1 父页核准行为和战术，再用独立原始技术文档、事件报告或可复现实现资料支持机理、NJS、检测字段与缓解效果。来源仅证明父行为时，缩窄或延期推断。

## 共享库与内容门禁

- 研究者检索现有 REF、CLM、CASE、DET、NJA、MIT，报告精确可复用对象和需要扩展之处。主 Agent 决定 reuse、extend、create、split 或 defer；新对象先用本批唯一暂存键，不分配 ID。
- 每个候选独立完成 retain、adapt 或 exclude 建议，双语范围、场景、攻防模型、机理、证据与研究限制，按 NJT-0001 的字段责任和论证深度检查，不以字数或子项数量凑齐。
- 防御建议必须指明可获得的事件源、字段、关联键、误报、盲区和控制施加点。脚本仅用于机械序列化、ID 同步、验证与构建。

## 并行安排

- 第一轮：一名 sub-agent 负责 T1485，一名负责 T1486；每人仅提交研究结果至各自交接文件或消息，不修改正式矩阵、准入决策或共享库。
- 暂存键前缀分别为 `TA0040-T1485-` 和 `TA0040-T1486-`。两份研究结果全部返回后，主 Agent 才裁决交叉边界、查重、分配正式 ID 并写入。

## 收敛注意事项

- 加密后删除原件、擦除备份、删除快照和磁盘擦除可能是一条事件链中的不同直接行为；单个 NJS 不得同时以结果、工具和媒介混合分组。
- “缓慢”“原生工具”“合法身份”只有在可证明独立改变痕迹及防守观察时才成为匿迹轴；动机、算法强度和勒索文案不足以成立 NJS。
