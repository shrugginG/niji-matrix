- 战术：TA0040 Impact；仅按固定 ATT&CK Enterprise 19.1 清单和当前 TA0040 正式矩阵计数。
- 当前批次：T1489、T1490、T1491、T1495、T1496，共五个父候选。
- 用户明确要求本批处理五项。每项由独立 sub-agent 研究并保留独立证据、taxonomy、双语内容与防御门禁；研究分两轮，主 Agent 等待五份结果后统一准入、跨技术收敛、查重和正式写入。
- BATCH-TA0040-001 已通过质量、Bundle 与双语 Web/API 门禁并处于 review。本批未通过全部候选门禁前，不开始下一批正式写入。

## 原生子技术规则

- ATT&CK 子项仅作广度先验：T1489 0、T1490 0、T1491 2、T1495 0、T1496 4；不得复制为 NJS。
- 子项须由稳定、可控匿迹变量划分，并证明痕迹变化、防守观察差异、前提、场景、证据和防御差异。
- T1491 对 T1491.001/.002 各给 planning-only 覆盖决议。T1496 至少检查两个实质不同的候选匿迹轴；若收敛为零或一个 NJS，须解释四类资源实现为何不能形成更多稳定原生轴。
- 零 NJS 可以成立，但 ATT&CK 无子项不能作为停止开放搜索的理由。

## 并行与共享库约束

- 第一轮：T1489、T1490、T1491。第二轮：第一轮全部返回后研究 T1495、T1496。
- 每名 sub-agent 只写各自 staging handoff，使用 `TA0040-<ATTACK-ID>-` 临时键；不得分配正式 ID或修改正式矩阵、准入决策、共享库、计划、brief 或集成摘要。
- 研究者运行共享库查找并报告 reuse/extend/create/split/defer 建议。主 Agent 在五份结果全部返回后统一解决语义身份与正式 ID。
- 每个候选必须提供可用于主审的完整双语父级/子项字段草稿，对照 NJT-0001；防御必须包含真实数据字段、窗口、关联、误报、盲区、调优与逐目标缓解应用。

## 证据门禁

- ATT&CK 19.1 父页只锚定父行为、战术和子项清单。原生子项、机理、字段、阈值、缓解效果与案例需结论级独立来源。
- 证据不足的轴保持 hypothesis 或 defer，并记录排除原因；不得为满足数量而制造 NJS、CASE 或通用防御对象。
