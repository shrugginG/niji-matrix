# BATCH-TA0040-003 研究与收敛约束

## 基线与范围

- 战术：TA0040 Impact；仅按固定 ATT&CK Enterprise 19.1 清单和当前 TA0040 正式矩阵计数。
- 当前批次依清单顺序处理五项：T1498 Network Denial of Service、T1499 Endpoint Denial of Service、T1529 System Shutdown/Reboot、T1531 Account Access Removal、T1561 Disk Wipe。
- 用户明确要求本批处理五项。每项由独立 sub-agent 研究，分两轮调度；主 Agent 等五份结果全部返回后才执行准入、跨技术收敛、查重、ID 分配和正式写入。
- BATCH-TA0040-002 已通过质量、五个 Bundle 和完整 Web/API 门禁并处于 `review`。本批未通过全部候选门禁前，不开始下一批正式写入。

| 候选 | 直接行为或状态对象 | 必须检查的相邻边界 |
|---|---|---|
| T1498 | 网络链路、协议或边界服务因攻击流量而无法为合法通信提供预期容量 | T1499 的端点/应用资源结果；T1496 的带宽使用服务于攻击者任务；C2 和僵尸网络只是控制/来源；反射与直接流量仅作 ATT&CK 广度参考。 |
| T1499 | 单个或一组端点、操作系统、服务或应用因资源耗尽或触发性崩溃而无法提供功能 | T1489 的管理控制式业务服务停止；T1498 的网络链路/边界流量；T1496 的资源消费任务；漏洞利用只有在完成 availability 结果时进入。 |
| T1529 | 主机、VM 或网络设备的系统生命周期进入关机或重启并造成访问中断 | T1489 的单服务停止；NJT-0096 的持久立足点电源状态连续性；NJT-0172 的受限启动防御缺失；正常维护、补丁和故障恢复。 |

| T1561 | 磁盘、卷或设备存储的内容/结构被擦除或破坏，使系统或数据不可用 | NJT-0156 的文件/对象级数据销毁；NJT-0188 的硬件消费固件破坏；T1490 的恢复副本抑制；NJT-0108 的 raw-storage view access；两项 ATT&CK 子项不直接转为 NJS。 |

## 原生 taxonomy 规则

- ATT&CK 子项只作 planning-only 广度先验：T1498 2（.001/.002）、T1499 4（.001–.004）、T1529 0、T1531 0、T1561 2（.001/.002）。不得复制名称或按资源层、平台、工具、目标类型直接划分 NJS。
- T1498、T1561 必须逐项给 coverage resolution；T1499 必须至少研究两个实质不同的匿迹轴，若最终为 0–1 个 NJS须解释四类实现为何在稳定性、痕迹、证据、兄弟边界或防御差异中坍缩。
- 原生子项必须具备攻击者可控稳定变量、痕迹变化、防守观察差异、前提、场景、结论级证据和不可互换防御。零 NJS 可以成立，但 ATT&CK 无子项不能作为停止搜索理由。

## 并行安排和写入边界

- 第一轮：T1498、T1499、T1529，各一名 sub-agent。
- 第二轮：第一轮全部返回后，分别研究 T1531、T1561。
- Sub-agent 只写 `planning/runs/BATCH-TA0040-003/<ATTACK-ID>-handoff.md`，使用 `TA0040-<ATTACK-ID>-` 临时键；不得修改正式矩阵、准入决策、共享库、计划、brief、ID 预留或集成摘要。
- 主 Agent 在五份交接全部返回前不分配任何正式 NJT/NJS/REF/CLM/CASE/DET/NJA/MIT/REL ID。

## 内容、共享库和防御门禁

- 每名研究者须完成 retain/adapt/exclude 建议、原生轴覆盖、完整双语父级/子项字段草稿、结论级来源和 NJT-0001 字段责任对照。
- 运行共享库查找并报告 reuse/extend/create/split/defer；相同产品或相似标题不构成共享对象身份。
- Detection Strategy/Analytic 必须提供真实数据源、通道、字段、逻辑、窗口、关联维度、误报、盲区和调优；Mitigation 提供措施及逐目标 use/effect/limitations。只替换名称的通用防御不准入。
- ATT&CK 父页只锚定父行为、战术和子项清单。NJS、机理、检测字段、阈值、缓解效果和案例归因必须有相应层级证据；不足时保持 hypothesis/defer，不制造 CASE 或子项。
