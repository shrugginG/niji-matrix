|---|---|---|

## 子技术规则

- 不导入 T1685.001–.006 作为 Niji 子技术。它们仅用于提醒研究覆盖 Windows/云/Linux 日志、工具功能和 UI 反馈等实现面。
- 六项 ATT&CK 子项要求逐项或逐簇覆盖表，并完成第二轮 taxonomy；Niji 子项只按攻击者稳定控制的匿迹变量、痕迹变化和防守观察差异划分。
- 初始候选轴至少审查：防御能力选择性退化、遥测生成或输送链静默、历史记录收缩、健康/界面反馈伪装、更新或恢复路径阻断。任何轴只有在拥有独立痕迹变化、兄弟边界、证据和防御差异时才正式化。
- 不按 Windows、Linux、云、EDR、AV、SIEM、服务名、日志文件或 ATT&CK 子项名称拆分。
- 每项保留机理必须形成“行为设计 → 痕迹变化 → 防守观察影响 → 匿迹效果”因果链；仅仅使工具不可用但立即产生清晰告警时，不得夸大为高强度匿迹。

## 内容与证据门禁

- 父行为以固定版本 ATT&CK T1685 页面锚定；工具健康、日志管线、界面欺骗和恢复阻断的细化结论必须由厂商文档、事件报告或可核查技术资料分别支持。
- 每项正式子技术需要独立证明攻击者可控变量、痕迹变化和防守观察差异；仅有 ATT&CK 子项名称或平台例子不够。
- Detection Strategy 必须把配置/服务变化、工具心跳、遥测量或序列断点及外部控制面状态关联起来；Analytic 要列出具体字段、窗口、误报、盲区和调优。
- Mitigation 必须说明权限隔离、篡改保护、异地/不可变留存、健康证明或独立观察如何改变 T1685 的机会和残余风险；不得只写“加强监控”。
- 父技术与每个子技术逐字段对照 NJT-0001 的定义、匿迹特性、边界、场景、攻防模型、机理和限制责任，但不复制其篇幅或对象数量。
- 对父子正文、威胁模型、限制和机理进行重复短语审查；双语必须保持相同范围、结论强度和不确定性。
- 脚本只用于 ID 分配、序列化、字段排序、同步、校验和 Bundle；正式读者正文、准入理由、taxonomy、Analytic 逻辑与 MIT Application 逐项人工收敛。
