# BATCH-TA0112-004 准入与 taxonomy 审查

本记录先于任何本批 NJT/NJS 或共享语义 ID 分配。基线为 ATT&CK Enterprise 19.1；以下结论分别按攻击者控制变量、痕迹差和防守观察结果作出。五项均为候选级裁决，最终是否进入 review 仍取决于逐项正式内容、证据、防御、Bundle 和 Web 门禁。

## T1689 — adapt

固定父项包含过时运行时、协议和启动组件的回退。TA0112 正式范围只收录“旧版本实际被使用，并相对批准基线失去日志、完整性或拦截能力”的版本介导防御退化；安装旧软件或允许兼容协议不等于完成。PowerShell Script Block Logging 的 4104 事件模型与 Windows Boot Manager 回滚保护是官方可验证的防守差分；ATT&CK 记录恶意降级实例，但不同实例的结果不能互相外推。与 T1600 分界为是否直接改变通信加密有效保护，与 T1601 分界为映像内容修改本身，与 T1685 分界为工具功能开关。置信度 medium。

ATT&CK 子项 0。开放搜索运行时遥测缺口、协商协议退化、启动信任回退、单纯版本更换。前两者若通信加密弱化归 T1600，若仅运行时缺少脚本审计则可形成独立观察轴；启动回退以受信启动/内核保护差为另一轴。拟建两个 NJS：旧运行时观察缺口与启动信任回退；它们按残余数据和恢复方法区分，而不是 PowerShell 与 Windows 品牌。协议加密分支让给 T1600，普通兼容性变更排除。首轴需进程版本、策略和真实脚本事件差；次轴需启动链测量、拒绝列表与实际安全组件状态。

## T1600 — adapt

父项锚定网络设备的通信加密保护下降。Cisco 对 2011–2012 年 IOS 恶意映像的取证直接显示 Diffie–Hellman 派生密钥材料被削弱，外观仍是加密流量，但离线解密成本下降；它支持“表面加密与有效强度分离”，不能推广为所有加速器关闭均导致明文。正式门槛是实际会话使用的密钥材料、算法或保护路径相对受批基线变弱。与 T1689 旧版本但保护等效、T1601 映像补丁、普通 TLS 兼容性回退划界。置信度 medium。

ATT&CK 子项 2：T1600.001 涉密钥空间/算法参数，T1600.002 涉硬件到软件加密路径。两项均为实现维度；前者是父级有效强度核心，后者只有进一步造成可证明的强度或完整性下降才满足同一父级结果，否则只是性能和信任路径变化。开放搜索加密外观不变而密钥熵下降、协商弱套件、硬件回退和明文路径；目前只有第一种具备直接事件证据，余项是平台能力或邻接变量，暂不建立 NJS。零子项不等于忽略 ATT&CK 子项。

## T1687 — adapt

固定父项是漏洞利用直接削弱防御。Google Threat Intelligence 对 CVE-2024-21338 的归纳报告了攻击者利用既有 AppLocker 驱动弱点获取内核能力并关闭安全工具，提供利用—结果链的公开证据；ATT&CK 的泛化描述不替代这条链。正式范围要求漏洞触发或恶意输入、同一防御组件的功能失效以及后继活动的时间与对象关联；只有提权、进入系统或安全服务正常重启不属于完成损伤。与 NJT-0110 的一般匿迹利用、NJT-0123 的直接工具损伤分别以漏洞机制和受损结果划界，可并列观察但不复写。置信度 medium。

ATT&CK 子项 0。开放搜索崩溃式失效、逻辑绕过、权限扩大后关停、云控制面安全边界缺口；现有直接案例只支持父级“漏洞触发—防御功能下降”，不能独立证明不同子类具有稳定、可观测且需不同防御方法的匿迹变量。因此本轮零 NJS；按 CVE、产品、漏洞类型或安全组件分类均拒绝。

## T1222 — adapt

ATT&CK 父项广泛覆盖文件与目录权限修改，但 TA0112 只保留安全工具可执行文件、保护性配置或审计工件的有效访问/执行控制遭攻击者改写并降低防御能力的分支。ESET 对 Grandoreiro 的原始分析观察到其向 Trusteer 二进制施加拒绝 ACL，意图阻止产品运行；公开片段主要证明恶意配置与目标，不提供每台受害设备上工具最终停用的完整结果。因此正式对象必须要求旧新权限、对象身份和消费者执行拒绝结果，不把其他勒索软件的普遍 Everyone 授权自动等同于防御损伤。合法所有权修复、普通读写权增加及后续载荷替换分别排除或归邻接技术。置信度 medium。

ATT&CK 子项 2：T1222.001 Windows、T1222.002 Linux/Mac，均为平台轴，不导入 NJS。开放搜索安全组件的执行拒绝、配置文件被攻击者取得写权、审计文件访问控制变化；仅执行拒绝有直接受损案例，其余需要具体消费者和控制结果，暂以父级描述并记为证据延期。零 NJS 的原因是跨平台机制相同而非平台数少。

## T1112 — adapt

ATT&CK 父项同时覆盖 Registry 驻留、执行、持久化和防御削弱；TA0112 仅保留 Registry 安全设置被改写且对应工具、系统策略或审计消费者实际采用并降低保护的分支。固定父页列出改变 Internet 安全级别、宏与凭据处理等实例，但这些实例的安全含义各异，不能把任意 Registry 写入认作本对象。NJT-0094 已拥有 Registry 驻留/持久化及跨 API 可见性，NJT-0125 拥有权威中心策略扇出，NJT-0123 拥有工具状态结果；本项聚焦本地 Registry 写入—消费者—有效控制的媒介因果链。置信度 medium。

ATT&CK 子项 0。开放搜索保护设置压低、审计开关、启动项持久化、隐藏键、宏或身份策略。后四者分别可能归 NJT-0094、认证/执行对象或现有安全工具对象；Registry 键类别不是稳定 NJS 变量。本轮零 NJS，除非能证明不依赖键名或产品的独立痕迹拓扑与防守方法。不能用持久化案例证明防御关闭。

## 共享库初步裁决

复用现有 REF-000188（T1112）、REF-000198（PowerShell 安全功能）、REF-000230（Sysmon Registry 事件）、REF-000391（T1211 边界）和已有受损工具/集中策略来源；四个缺失的 ATT&CK 父来源及 Cisco、Microsoft、Google、ESET 的结论级来源需按规范 URL 新建，不能重复已有记录。不同候选的 DET/NJA 数据关联、恢复动作和 MIT 受控面不相同，暂不合并为一个通用防御对象。CASE 仅记录公开来源真正观察到的事件，不从 ATT&CK 示例自动复制成案例。
