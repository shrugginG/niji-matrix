# BATCH-TA0112-004 五候选防御削弱开发

基线固定为 `matrix.yaml` 的 MITRE ATT&CK Enterprise 19.1。本轮用户要求一次处理五个匿迹技术，故在 TA0112 已冻结的 18 个父候选中，取尚未完成且原规划紧邻的 T1689、T1600、T1687、T1222、T1112。五项是准入研究目标，不预设五个 NJT 或任何 NJS 数量。已有 T1685、T1686、T1484、T1666 的证据、taxonomy、双语正文、防御、质量、Bundle 与 Web 门禁均通过并处于 review；TA0112 目前正式完成 4/18，其他战术或 TA0005 清单不计入分母。

本批超过默认一至三候选的理由是用户明确指定五项。规模例外不降低逐候选质量：先分别完成证据、retain/adapt/exclude、ATT&CK 子项覆盖与开放 taxonomy 搜索；再按 T1689、T1600、T1687、T1222、T1112 的顺序逐项完成共享库决议、正式写作、NJT-0001 字段深度对照、防御实现、机器和双语 Web 门禁。T1687 是复杂候选，若其直接损伤因果链不足，必须 defer 子项或 exclude，而非用近邻 T1211 的证据代替。任何当前候选未过门禁时，不开始下一候选的规范对象写入；每项研究可先进行但不得提前占用正式 ID。五项全部收敛后才将本批置于 review。

## 候选直接对象与边界

- T1689 Downgrade Attack：直接对象是受防御约束的运行组件、协议或启动链的有效安全版本与功能，需证明旧版本被实际使用且缺失某项防御能力。与 T1600 的通信加密强度、T1601 的映像修改和 T1685 的工具功能关停以直接结果划界；单纯兼容性模式或安装旧软件不自动准入。ATT&CK 19.1 无子项，必须开放搜索运行时遥测、协议保护与启动信任三个可能的观察轴。
- T1600 Weaken Encryption：直接对象是网络设备实际提供的通信保密性或完整性，不是普通版本号。ATT&CK 两个实现子项 T1600.001（Reduce Key Space）和 T1600.002（Disable Crypto Hardware）只作广度先验；须区分可协商/配置的保护强度下降、加密路径缺失，以及 T1689 的一般版本回退。必须有配置前后态和真实会话或路径结果，不能仅凭硬件禁用命令推断明文。
- T1687 Exploitation for Defense Impairment：直接对象是漏洞触发后防御组件预防、检测或响应能力的实证下降。ATT&CK 无子项；利用链、崩溃/绕过结果与后续活动须有时序和对象一致性。T1211/NJT-0110 处理一般匿迹利用，T1685/NJT-0123 处理工具状态改变；本候选仅保留漏洞利用直接造成防御损伤的特定因果结果，不按 CVE、产品或漏洞类型拆子项。
- T1222 File and Directory Permissions Modification：直接对象是文件系统权限或审计控制的有效访问/观察边界变化。ATT&CK T1222.001（Windows）与 T1222.002（Linux and Mac）是平台实现，不得复制为 NJS。须与一般取权、持久化载荷替换、T1112 Registry 介质和 T1685 工具范围收缩划界；仅 chmod、ACL 写入或所有权变化不足以证明防御削弱。
- T1112 Modify Registry：直接对象是 Registry 中被防御消费者实际读取的保护、审计或响应配置。ATT&CK 无子项，TA0003 的 NJT-0094 已拥有 Registry 驻留及持久化结果，TA0112 不复写该对象；纯配置介质不是 NJS 变量。须连接写入者、键值前后态、消费者版本及保护结果，并与 NJT-0125 集中策略发布、NJT-0123 工具功能和特定认证/宏设置对象划清结论归属。

## 证据与共享库

ATT&CK 固定父页只锚定候选行为与战术，不自动证明子项、机理或防御效果。优先寻找原厂平台说明、官方事件/漏洞分析和直接观测案例；配置或 API 文档只支持可实施数据要求，不能当作在野攻击案例。每个候选分别记录直接证据、推断、正常反例与研究限制。首先用 library catalog、URL/标识符和语义查询检查 REF、CLM、CASE、DET、NJA、MIT、REL；相同来源复用，结论不变才扩展 Claim/Case，检测数据和控制动作不相同则拆分。主 Agent 统一分配所有正式 ID，临时研究键限定在本目录。

正式父子项均需以 NJT-0001 的字段责任和双语论证深度为基线，完整覆盖定义、匿迹特性、边界、场景、攻防模型、机理、证据和限制。NJS 只按稳定可控变量、痕迹变化、防守观察差异与独立防御价值建立，不翻译 ATT&CK 子项。每个正式对象要有适用的 DET→NJA 与 MIT Application，不能只替换标题。顺序完成共享库查重、ID sync、`make quality`、逐技术 Bundle、71 项 Web 测试与双语页面/API QA；人工领域评审前保持 review。
