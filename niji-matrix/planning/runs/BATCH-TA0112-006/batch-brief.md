## 候选直接对象与边界

- T1556 Modify Authentication Process：ATT&CK 19.1 有九个子项，必须完成逐簇覆盖表与第二轮 taxonomy。TA0003 已有 NJT-0093“认证路径持久操纵”及两项原生 NJS，需判断 TA0112 是否存在不同的直接防御削弱结果，还是认证验证/策略例外已经由同一 owner 完整表达。认证秘密获取、账户级认证器、令牌伪造和单纯日志关闭分别归 Credential Access、T1098、令牌对象和工具/记录对象。不得按 PAM、域控制器、网络设备、联合身份或 MFA 产品复制子项。
- T1578 Modify Cloud Compute Infrastructure：ATT&CK 19.1 有五个子项，触发至少两个独立匿迹轴审查。直接对象候选是 VM/实例、快照、映像或相关计算状态的生命周期变化是否导致取证状态、监测覆盖或控制注册发生可验证差异；与 T1666/NJT-0126 的资源 ancestry、云区域选择、普通资源创建、Impact 破坏和持久计算入口划界。创建、删除、克隆或快照操作本身不证明失防。
- T1601 Modify System Image：ATT&CK 两个子项只作映像补丁和降级实现广度。直接对象候选是网络设备运行/持久映像被攻击者修改后，可信启动、完整性验证、遥测或安全功能出现结果差；与 NJT-0127 版本回退、NJT-0128 有效加密损伤、固件/启动持久化及一般恶意映像执行划界。映像 hash 不同不等于防御削弱。
- T1599 Network Boundary Bridging：ATT&CK 一个子项只作研究线索。直接对象候选是攻击者建立跨安全边界的桥接路径，使原有分段、检查或策略执行被绕过；需与普通隧道/C2、横向移动、网络设备配置持久化和 NJT-0124 防火墙策略削弱划界。必须证明两侧安全域、桥接前后可达性与检查路径差。
- T1690 Prevent Command History Logging：ATT&CK 无子项，仍需开放搜索。直接对象是交互式命令在记录前被攻击者有意排除于历史持久化，而不是事后删除已有历史、非交互 shell 默认不记历史、隐私/合规配置或整体日志工具停用。与 NJT-0123 的入库前遥测抑制和 NJT-0112 的事后证据擦除按记录生命周期与数据 owner 划界。

## 证据、taxonomy 与共享库约束

固定 ATT&CK 父页只锚定父行为与 TA0112 映射。每项直接结果、机理、NJS 与防御数据假设还需官方平台文档、原厂技术分析或现场事件支持。T1556 九子项需要覆盖表和第二轮 taxonomy；T1578 五子项至少审查两个不同变量；其余父项即使子项少或为零，也必须开放检查时序、来源、可见性、控制面分离和生命周期变量。任何 NJS 都必须具备稳定攻击者变量、独立痕迹、防守观察差、前提、案例/证据和目标化防御；平台、产品、API、映像格式、资源类型、shell 名或 ATT&CK 子项名称不是分类依据。

共享库按 ATT&CK ID、CVE/公告、官方 URL 和语义指纹查重。T1556 优先复核 NJT-0093、DET-000073、MIT-000073 及其来源，而不是改名复制。云、网络设备和 shell 数据源若逻辑、关联窗口或控制动作不同则拆分；只有语义完全一致时复用/扩展。正式 ID 由主 Agent 在每候选准入和 taxonomy 收敛后分配。脚本只用于验证、机械序列化、ID、Bundle 和 catalog，不批量生成读者正文。

所有 admitted 父子项需完整双语覆盖定义、匿迹特性、范围边界、应用场景、攻击者/防守方模型、机理、证据和限制，并建立可实施 DET→NJA 与逐目标 MIT Application。exclude 只保留决策和必要来源。本批五项全部完成后才更新 integration summary 和批次 review；人工领域评审前不得 published。
